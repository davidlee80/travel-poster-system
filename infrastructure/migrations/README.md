# 数据库迁移

前向单向迁移。执行器见 [`packages/db/src/migrate.ts`](../../packages/db/src/migrate.ts)。

## 命令

```bash
pnpm db:status     # 已应用 / 待应用 / 校验和漂移
pnpm db:migrate    # 应用全部待执行迁移
```

需要 `DATABASE_URL`。可用 `MIGRATIONS_DIR` 覆盖目录（测试用）。

## 命名规范

```
NNNN_snake_case_name.sql
```

四位数字版本号 + 下划线小写名。**不允许大写与连字符** —— Linux 文件系统区分大小写，命名必须确定（设计稿 22.3.3）。版本号必须唯一，允许不连续（便于并行分支各占号段）。

## 三条硬规则

**1. 不写 `down`。** 破坏性变更走 expand-backfill-contract 三步，每步都是独立的前向迁移：

```
0010_expand.sql     新增列/表，可空或带默认值，旧代码不受影响
0011_backfill.sql   回填数据，可重复执行
0012_contract.sql   收紧约束、删除旧列
```

回滚靠部署上一版应用代码，不靠反向 SQL —— 有数据的生产库上反向 SQL 几乎总是错的。

**2. 已应用的文件不可修改。** 执行器记录每个迁移的 SHA-256。文件被改动时 `db:migrate` 报错而不是静默跳过 —— 内容漂移意味着「已应用的历史」与「仓库里的历史」不一致，必须人工介入。需要修正就新增一个前向迁移。

**3. 每个迁移是一个事务。** PostgreSQL 的 DDL 是事务性的，失败即整体回滚。因此单个迁移文件应当是一个逻辑变更单元，不要把互不相关的变更塞进同一个文件。

## 并发安全

执行器使用 `pg_advisory_lock`，K8s 滚动更新时多个实例同时启动也只有一个执行迁移，其余等待。
