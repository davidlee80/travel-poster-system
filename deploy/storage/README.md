# 导出桶的生命周期规则（TP-6-15，设计稿 19.3、15.4、R-51）

`exports-lifecycle.json` 是**导出桶**（`S3_BUCKET_EXPORTS`）的桶级生命周期规则。
素材桶不挂任何规则 —— 素材 URL 会被写进 ViewModel 并永久保存（19.3）。

## 只有 `users/` 前缀挂规则，`anon/` 前缀**不挂**

这是 R-50 的硬约束在部署侧的表现：

```text
users/   90 天桶级规则          → 对象存储自己过期
anon/    没有规则               → retention-worker 按数据库归属显式删除
```

`anon/` 前缀下**混有已升级 / 已归并用户的长期数据**。归并只改数据库归属、
对象零搬运（13.9.4 / R-50），因此一个注册了三年的用户名下仍可能有当年匿名期
产出的、键在 `anon/` 下的 PDF。挂上 90 天规则会把它们静默删掉 ——
而对象存储的生命周期规则没有「例外名单」这种东西，它只认前缀。

因此 `anon/` 下的两种到期都由 `retention-worker` 处理：

| 到期类型     | 触发条件                        | 实现                                         |
| ------------ | ------------------------------- | -------------------------------------------- |
| 匿名归属到期 | `anon_expires_at` + 30 天宽限   | `purge.ts` 的 `beforeDelete` 钩子（TP-6-14） |
| 导出物 90 天 | `exports.created_at` 超过 90 天 | 见下方「尚未实现的一半」                     |

## 尚未实现的一半

R-51 的第二种到期（「按 `exports.created_at` 扫描，仅删已归并 / 已升级用户
遗留在 `anon/` 下的导出物」）**本轮未实现**。当前状态：

- 纯匿名用户到期时，其 `anon/` 对象随行清理（TP-6-14 已实现）；
- 注册用户的产物落 `users/` 前缀，由 90 天桶级规则回收；
- **缺口**：已归并用户遗留在 `anon/` 下的旧产物既不挂规则、也没有扫描任务，
  会长期留存。

它不阻塞 V1 内测：这类对象的产生前提是「用户在匿名期导出过、之后注册并归并」，
在内测规模下量级极小，且它们是可再生派生物（源数据长期保留，同参数重导出
即可，R-51）。真正的风险是存储成本随时间线性累积而没人看得见 ——
因此这一项写进实施记录的交付边界，而不是留在代码注释里。

## 本地应用（MinIO）

`infrastructure/docker-compose.yml` 的 `minio-init` 会自动应用它。
手工应用：

```bash
mc ilm import local/tps-exports < deploy/storage/exports-lifecycle.json
mc ilm rule list local/tps-exports
```

## 生产应用

需要对象存储的桶管理权限（实施计划第七章的开工前确认事项之一）。
Helm chart 不管这件事 —— 桶策略与生命周期属于存储侧的一次性配置，
放进 chart 会让每次应用发布都去改一次桶配置。
