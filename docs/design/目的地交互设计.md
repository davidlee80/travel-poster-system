建议把原来的“出发地 → 单个目的地”改为**可排序的行程节点列表**。每个目的地作为独立节点，分别设置驻留时间；用户只需填写出发日期和每站晚数，系统自动推算各站日期及返程日期。

## 关键交互说明

### 1. 支持两种时间设置方式

**按驻留晚数自动排期**

- 用户设置统一的出发日期；
- 每个目的地填写驻留晚数；
- 系统自动计算到达、离开及返程日期；
- 修改前一站晚数后，后续日期自动顺延。

**为每站设置具体日期**

```text
东京    到达日期 [04/01]    离开日期 [04/04]    共 3 晚
京都    到达日期 [04/04]    离开日期 [04/06]    共 2 晚
```

适用于已经预订酒店、航班或存在跨日交通的用户。两种模式可以切换，切换时保留已有数据并提示日期变化。

### 2. 添加与调整目的地

- 点击“添加下一个目的地”新增节点；
- 支持输入城市、景区或区域，并通过联想搜索选择；
- 左侧拖拽手柄 `⠿` 用于调整目的地顺序；
- 删除非空节点时进行二次确认；
- 第一站也可以设置为“从其他城市抵达”。

### 3. 驻留时间建议使用“晚”

住宿型旅行中，“3天”容易产生是否包含到达、离开当天的歧义，建议主单位使用“晚”，同时辅助展示：

```text
3 晚 · 约 4 天
```

对于不过夜的目的地，提供：

```text
□ 当日往返 / 途经，不住宿
```

勾选后驻留时间显示为“0晚”，但仍保留该行程节点。

### 4. 交通时间处理

目的地之间可选填交通方式和耗时：

```text
东京 → 京都
[新干线 ⌄]  [约 2小时15分]  [出发时间 09:00]
```

未设置交通时，不阻断用户继续操作；进入详细规划阶段后再提醒补充。如果交通跨夜，则应占用日期，并自动调整下一站抵达时间。

### 5. 异常与校验状态

- 目的地与出发地相同：提示确认，不直接报错；
- 驻留晚数为空：该节点标红，并提示“请设置驻留时间”；
- 日期重叠：提示“京都到达日期早于东京离开日期”；
- 驻留时间过长：只做轻提示，不限制用户；
- 至少保留一个目的地；
- 最后一站变化时，返程日期自动更新。

## 视觉样式建议

保持图片中现有的卡片式视觉：

- 每个目的地使用浅灰色子卡片；
- 当前正在编辑的节点使用蓝色描边；
- 自动计算出的日期使用灰色辅助文字；
- “添加目的地”使用虚线边框或浅蓝按钮；
- 行程概览固定放在模块底部，修改后实时更新；
- 目的地超过 5 个时，列表区域内部滚动，概览保持可见。

该结构既能满足常规的“多个城市分别住几晚”，也能兼容当日往返、跨夜交通、不同返程城市和已确定日期等复杂场景。
