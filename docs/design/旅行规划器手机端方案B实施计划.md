# 旅行规划器手机端方案 B 实施计划

> 编制日期：2026-09-18  
> 状态：实施计划，尚未开始本计划中的移动端改造  
> 方案：桌面保留三栏，手机采用专用单栏向导，共享数据与业务逻辑  
> 首批范围：第 0 页、第 1 页及其依赖的导航、摘要、搜索和底部操作

## 1. 目标与范围

让用户在手机上清楚知道当前填写位置，能够单手完成主要操作，在输入、切换步骤、展开摘要和恢复草稿时保持连续体验。

本期交付范围：

- 桌面端保留当前三栏结构和主要操作方式。
- 手机端采用“顶部当前步骤与保存状态 + 单栏内容 + 底部操作栏”。
- 第 0 页选择卡片后解锁第 1～9 步，所有入口采用一致规则。
- 第 0 页手机端采用两列两行布局，正常字号、竖屏浏览时，四张卡片及“继续”按钮在首屏完整可见，无需滚动或滑动寻找选项。
- 首先完成第 0～1 页试点，再推广到第 2～9 页和生成过程弹窗。
- 平板端沿用现有双栏基础，验证手机与桌面之间的布局过渡。

本期不新建独立手机站、原生 App、小程序或 PWA；不把每个字段拆成独立页面；不改后端接口、计费、生成规则和答案契约。生成结果详情、导出文档和第 10 步行前准备中心的全面手机改版另立任务；本期验证其入口不受影响。

前置核查项：

1. 检查仓库约束、当前改动和运行方式，记录桌面与手机基线截图。
2. 核对 `entry-routes.ts` 的字段显示规则与 `step-state`、触发器及提交校验是否一致。源码注释表明隐藏字段与必填规则仍存在待对齐事项；先复现四种路线，再决定是否需要独立的业务修复。不能通过手机端跳过校验掩盖问题。
3. 当前验证曾发现 `@tanstack/react-virtual`、`fuse.js` 本地依赖缺失，以及 schemas 编译产物落后于源码；实施时按锁文件恢复依赖、刷新必要产物后重新检查，不预设问题仍然存在。
4. 当前 CSS 作用域检查曾报告城市搜索选择器未以 `.planner` 开头。记录基线；本次触及的选择器需符合规范，剩余问题单独跟踪，不把全量检查失败报告为通过。

## 3. 布局与视觉规范

### 3.1 初始断点

| 视口宽度 | 布局 |
| --- | --- |
| 小于 768 CSS px | 手机单栏向导，步骤与摘要按需打开 |
| 768～1199 CSS px | 平板双栏，摘要使用面板 |
| 不小于 1200 CSS px | 桌面三栏 |

沿用当前主要断点作为起点；若内容出现拥挤，依据实测调整。布局以 CSS 为主，不按 User-Agent 分流。需要行为差异时使用统一的媒体查询监听，确保服务端与客户端初次渲染一致。

### 3.2 手机视觉基线

- 复用当前颜色、字体、圆角、图标和卡片插画，不引入另一套视觉主题。
- 页面两侧初始间距 16px，窄屏可降为 12px；主要输入文字以 16px 为起点。
- 主要按钮高度不小于 44px；图标按钮触控区域以 44～48px 为目标。
- 第 1～9 页单列显示主要字段；只有确实能容纳的短字段使用双列，不靠缩小文字解决拥挤。第 0 页单独采用两列两行卡片布局。
- 第 0 页优先保留完整标题、关键状态标签与选中反馈；插画保持比例并压缩高度，说明采用简短文案，空间不足时收起装饰插画和重复引导文案，不缩小关键文字来强行塞入首屏。
- 单屏内容允许纵向滚动，页面主体不应横向溢出；说明文字与错误信息允许换行。
- 使用动态视口高度和安全区留白；弹出键盘时输入框、错误提示和操作按钮不能被遮挡。

## 4. 手机交互设计

### 4.1 顶部与步骤导航

- 顶部常驻当前步骤名称、简短保存状态和“全部步骤”入口；账号和重新开始收纳到次级入口。
- 第 0 页显示“开始规划”；后续页面显示“第 N 步 / 9 · 步骤名称”，不要把步骤位置当作画像完成度。
- 用当前步骤信息替代手机上常驻的十个数字横向步骤条。
- “全部步骤”打开导航面板，显示完整名称、当前状态和可访问状态。
- 未选择第 0 页卡片时，第 1～9 步禁用，面板和第 0 页均显示“请先选择旅行准备状态”。
- 选中任意卡片后立即解锁；返回第 0 页不清空选择，切换卡片保留已有答案，沿用现有路线过滤规则。

### 4.2 第 0 页

- 四张卡片采用两列两行等尺寸网格，首屏同时完整展示四个选项；不使用轮播、横向滑动或默认折叠，不需要滚动才能看到下排卡片。
- 卡片顺序保持与桌面一致，按从左到右、从上到下阅读；整张卡片可点击，完整标题、关键状态标签和选中标记始终可见。
- 第 0 页采用专用紧凑外壳：精简顶部品牌与页面标题，减少上下留白，隐藏非必要进度统计和重复说明，为四卡网格分配主要可用高度。
- 高度按实际可视区域计算，扣除顶部、底部“继续”操作栏、必要间距和安全区后分配两行卡片；考虑浏览器地址栏展开时的空间，不能仅以设备物理屏幕高度验收。
- 优先压缩装饰插画、重复引导语和卡片内边距，必要时隐藏插画；标题和关键标签允许换行，不截断、不省略关键含义，不使用整体缩放或隐藏溢出来制造一屏效果。
- 默认字号、竖屏下同时保证四卡完整可见、“继续”按钮可见且无遮挡。横屏、极低可用高度或用户放大文字时，允许纵向滚动以保留可读性与完整操作，不强制锁定页面高度。
- 用边框、勾选标记和可访问语义共同表达选择，不能只靠颜色。
- 选中卡片后留在本页，由底部“继续”进入第 1 页，避免用户误触后直接跳页。
- 未选择时“继续”禁用，并有可见原因；选择后解锁导航和继续按钮。
- 刷新后恢复已选路线；旧草稿未选择路线时先回第 0 页，保留答案。

### 4.3 第 1 页与目的地编辑

- 每个目的地独立成卡片，展开后编辑城市、抵达日期、驻留天数与到达方式。
- 已填写卡片可收起为“城市 + 抵达日期 + 驻留天数”摘要；新增卡片默认展开。
- 首期使用明确的展开/收起操作，不因每次输入或失焦自动折叠。
- 发生校验错误时自动展开对应卡片、滚动到相关字段并聚焦。
- 删除、增减天数等按钮具有清晰名称和足够触控区域；保留现有删除与数据处理规则。
- 日期输入首期沿用原生控件，验证 iOS、Android 和微信中的可用性，再决定是否需要定制日期面板。
- 手动修改抵达日期时复用现有逐级校验；自动缩短驻留时间后，提示具体目的地及新天数。
- 不足最小驻留时间 1 天时保留原数据，在日期字段附近展示“选中的时间不合理”；不能只在列表最底部显示错误。
- 多目的地发生自动调整时，提示应可读、可被辅助技术感知，且不抢走当前输入焦点。

### 4.4 城市搜索

- 手机使用全屏搜索面板，顶部固定搜索框与关闭按钮，结果区域独立滚动。
- 复用现有检索、虚拟列表、地点对象和选择回调。
- 明确区分加载、无结果与请求失败；选中结果后关闭面板并更新原卡片。
- 搜索时键盘不能遮住所有结果，清空和关闭操作易于点击。
- 关闭面板恢复原位置；恢复焦点时避免非必要地再次唤起键盘。

### 4.5 摘要与确认

- 提供固定位置的“旅行摘要”次级入口，首选放在顶部，避免与底部主按钮争夺空间。
- 手机摘要使用近全屏面板，沿用当前摘要分组、状态和字段回跳逻辑。
- 普通关闭返回原步骤、原滚动位置；点击某项“修改”则关闭摘要，展开并定位到来源字段。
- 未解锁时摘要入口和其中的回跳操作也遵守第 0 页门槛。
- 第 9 页按类别展示可展开摘要，提供明确修改入口；从确认页发起编辑后显示“返回确认”，完成修改后可回到原摘要区域。
- “返回确认”的来源状态属于临时 UI 状态，普通填写流程不应出现这个按钮。

### 4.6 底部操作与弹层

- 底部只保留当前任务的主要操作：上一步、下一步，或确认页的生成按钮。
- 保留底部安全区和内容留白，最后一个字段可以滚动到操作栏上方。
- 保存失败、余额不足、尚未选择卡片等阻止操作的原因在手机上必须可见。
- 面板打开时隐藏或禁用背景操作栏，一次只允许一个交互面板处于前台。
- 面板具备明确关闭按钮、语义标题、焦点约束、背景滚动锁定和关闭后的焦点恢复。
- 手机系统返回优先关闭当前面板；只消费本次面板拥有的历史记录，不循环增加记录、不阻止用户最终离开页面。
- 不将普通步骤切换改造为一套新路由；刷新、浏览器前进/返回和显式关闭组合必须单独测试。

## 5. 技术组织与文件范围

| 文件或模块 | 计划修改 |
| --- | --- |
| `apps/web/src/components/planner/Planner.tsx` | 组装手机外壳，协调面板、摘要回跳和确认页返回上下文 |
| `shell/TopBar.tsx` | 手机当前步骤、保存状态、步骤及摘要入口 |
| `shell/StepNav.tsx` | 手机面板展示，复用解锁规则与步骤状态 |
| `shell/SummaryRail.tsx` | 共用摘要内容，适配手机面板 |
| `StepPage.tsx` | 手机内容间距、底部操作、错误定位配合 |
| `Step0Entry.tsx` | 紧凑卡片布局和选择反馈 |
| `controls/PlaceControls.tsx` | 目的地折叠摘要、展开状态及字段附近的日期反馈 |
| `controls/CityCombobox.tsx` | 完善手机搜索面板、焦点和键盘行为 |
| `TravelersControl.tsx`、`BudgetControl.tsx` 及其他复杂控件 | 在推广阶段逐项适配，不一次性重写 |
| `GenerationDialog.tsx` | 验证手机进度、失败重试与关闭行为 |
| `apps/web/src/app/planner.css` | 统一手机断点、布局、触控尺寸、安全区和滚动规则 |
| `apps/web/src/lib/planner/state.ts`、`persistence.ts`、`step-state.ts` | 原则上复用；仅在证实入口守卫或恢复存在缺口时做针对性修改 |

组织原则：

1. 业务状态、字段契约、校验和自动保存只有一份；不新增 mobileAnswers 或手机专用请求格式。
2. 优先响应式布局和共用内容，不同时挂载两份带输入框的桌面/手机表单，避免重复 ID、重复保存和状态不一致。
3. 面板关闭、滚动锁定、焦点恢复若确有多处复用，再抽取小型共享组件或 hook；不搭建通用弹窗框架。
4. 目的地折叠状态不写入后端契约；增删目的地后不能将展开状态错配给其他城市。若需要稳定 UI 标识，仅在前端维护。
5. CSS 修改按组件与断点就近组织，所有新增规则遵守仓库的作用域要求。

## 6. 分阶段实施与完成条件

### P0：基线与依赖核查

- 检查实际分支、工作区改动、依赖和 schemas 产物。
- 记录第 0～1 页的桌面与手机截图，复现四种入口路线、草稿恢复和日期联动。
- 明确现有校验、构建和样式检查失败是否与本任务有关。
- 在现有品牌样式下确定手机第 0 页、第 1 页、导航与搜索面板的布局参考。

完成条件：有可复现基线、问题清单和可评审的首批布局参考；隐藏字段阻塞问题已有明确结论或独立处理任务。

### P1：手机外壳与导航

- 完成顶部当前步骤、导航面板、摘要入口与底部操作布局。
- 接入第 0 页解锁规则，补齐手机可见的禁用原因。
- 实现面板关闭、焦点、背景滚动与返回行为。

完成条件：未选择不能绕过第 0 页；选择后自由访问后续步骤；手机无重复导航或操作栏遮挡；桌面三栏保持正常。

### P2：第 0～1 页试点

- 完成第 0 页首屏两列两行入口卡片、目的地展开/收起、搜索面板与日期就近提示。
- 处理键盘、删除目的地后的状态和校验定位。
- 验证四种路线的实际可填写路径，以及 1 个、3 个和 5 个目的地场景。

完成条件：第 0 页在目标手机竖屏、默认字号下无需滚动即可完整看到四卡与“继续”按钮；真实手机可以完成“选卡 → 填写可见字段 → 搜索城市 → 修改日期 → 查看摘要 → 继续”的试点路径；业务校验缺口不得以 UI 验收通过替代。

### P3：推广至第 2～9 页

- 按步骤检查同行人、预算、节奏、偏好及条件展开等复杂控件。
- 长列表采用可回顾的分组或折叠；保留原字段顺序和必填语义。
- 完成第 9 页修改后返回确认的流程，以及生成中、失败和重试状态适配。

完成条件：可完成一次完整问卷和生成交互；授权、登录、额度等原有限制继续有效。

### P4：回归与交付

- 完成测试矩阵、截图比对和桌面回归，修复本次引入的问题。
- 记录已知限制、环境问题及未覆盖设备；提供逐项验收结果。
- 将变更按“外壳与导航”“第 0～1 页试点”“其余步骤推广”组织为可独立评审的提交。

完成条件：验收清单有证据，相关检查通过或明确标识被既有问题阻塞；按项目发布流程上线，不把文档落盘视为部署授权。

依赖顺序：P0 → P1 → P2 → P3 → P4。试点交互稳定后再推广，避免在九个步骤同时返工。不在基线核查前承诺固定工期。

| 异常状态 | 保存失败、加载失败、无搜索结果、登录失效、生成失败和额度不足 |
| 无障碍 | 键盘访问、可读标签、选中/禁用语义、错误播报、200% 文字放大 |
| 桌面回归 | 三栏、字段显示、摘要回跳、目的地联动、生成入口与弹层 |

自动化分工：

- 单元测试：复用并扩展入口守卫、恢复、日期联动等行为测试。
- 组件测试：验证导航禁用、提示文本、卡片展开状态等；现有服务端静态渲染测试不能替代真实点击、焦点和滚动验证。
- 浏览器测试：验证选卡解锁、搜索选择、错误定位、面板关闭、返回确认和草稿恢复等关键路径。
- 真机检查：覆盖软键盘、原生日期控件、安全区、浏览器返回和微信行为；不能仅依赖桌面模拟视口。

执行时按实际改动选择检查范围，建议命令：

```powershell
pnpm --filter @tps/schemas run build
pnpm --filter @tps/web exec vitest run src/components/planner/shell/StepNav.test.tsx src/components/planner/controls/PlaceControls.test.ts src/lib/planner/step-state.test.ts src/lib/planner/persistence.test.ts
pnpm --filter @tps/web run typecheck
pnpm --filter @tps/web run lint
node tools/scan-css-scope.mjs
pnpm --filter @tps/web run build
git diff --check
```

新增加的手机交互测试应一并纳入执行；最后运行前端完整测试集。环境导致命令无法执行时记录具体原因，不能通过关闭校验、删除失败测试或修改锁文件绕过问题。

## 8. 风险与控制

| 风险 | 控制措施 |
| --- | --- |
| 手机与桌面各自维护表单导致行为分叉 | 共用业务状态和字段组件，布局差异限制在外壳及必要控件 |
| 手机样式覆盖桌面 | 规则限定到组件及断点，每阶段都检查桌面基线 |
| 键盘覆盖固定底栏 | 动态视口、安全区、内容留白结合真机验证；必要时键盘打开期间收起非必要操作 |
| 面板历史记录导致返回异常 | 明确记录所有权和清理流程，测试关闭、返回、前进、刷新组合 |
| 隐藏字段仍阻塞下一步 | P0 单独复现并确定业务处理方式，不偷偷放宽手机校验 |
| 卡片折叠使错误不可见 | 校验失败时先展开，再滚动和聚焦 |
| 原有依赖或 CSS 问题影响验收 | 保存基线、区分新增与既有问题，发布前明确其影响 |
