我看了附件里的页面结构。现在这版已经有比较完整的产品骨架：顶部品牌与保存状态、左侧 10 步导航、中间问卷主体、右侧规划进度摘要，而且第 0 步用了 4 张带插画的选择卡片来降低填写压力。这个信息架构本身是合理的，不建议推翻；更值得做的是把视觉从现在略偏“后台/工具型”的感觉，调整成一种 **安静、轻盈、有旅行期待感的沉浸式问卷**。附件中现有页面也已经配置了 Noto Sans SC、Noto Serif SC 和 Inter 三套字体，这给进一步建立更精致的字体层级提供了很好基础。

我会把新版的设计方向定成：

> **Soft Journey / 柔和旅途**
> 像坐在一家安静的旅行咖啡馆里慢慢规划行程，而不是在填写一张很长的表单。

### 1. 配色：不要“旅游网站蓝”，改成低饱和自然色

长时间问卷最重要的不是“鲜艳”，而是**低刺激 + 足够层级**。我建议页面不要使用纯白背景，也尽量不要大面积高饱和蓝色。

| 用途       | 建议颜色                  | 视觉感觉       |
| -------- | --------------------- | ---------- |
| 页面大背景    | `#F6F5F1`             | 温暖象牙灰      |
| 主内容卡片    | `#FFFFFF` / `#FCFBF8` | 干净但不刺眼     |
| 主文字      | `#25312D`             | 深墨绿色，比纯黑柔和 |
| 次文字      | `#6F7772`             | 柔和灰绿       |
| 品牌主色     | `#5F806F`             | 鼠尾草绿       |
| Hover    | `#EDF3EF`             | 很浅的自然绿     |
| Selected | `#E3EEE8`             | 选择反馈       |
| 强调暖色     | `#D79B72`             | 陶土橙        |
| 辅助黄色     | `#E8C982`             | 阳光感        |
| Border   | `#E3E5E0`             | 几乎不可感知的边界  |

尤其不建议把“必须满足 / 不要 / 待确认 / 优先”全部做成强烈红黄绿标签。它们长期同时出现，会让界面非常像项目管理工具。

可以改成：

**必须满足** → 柔和陶土红
**明确不要** → 灰紫
**待确认** → 暖黄色
**优先满足** → 鼠尾草绿

颜色只作为辅助识别，**文字和 icon 才承担主要语义**。

---

### 2. 页面背景：不要纯色，做极轻的“旅行氛围”

背景可以做成非常克制的自然渐变：

```css
background:
  radial-gradient(
    circle at 15% 0%,
    rgba(215, 225, 216, .45),
    transparent 32%
  ),
  radial-gradient(
    circle at 90% 15%,
    rgba(241, 222, 194, .32),
    transparent 28%
  ),
  #F6F5F1;
```

这样第一眼不会觉得“这是管理后台”。

但一定不要：

* 大面积风景照片
* 云、山、飞机反复铺满背景
* 很明显的渐变
* 毛玻璃到处使用

旅行氛围应该来自**色彩、插画和留白**，而不是装饰物数量。

我甚至会在页面非常淡地加入类似：

`Tokyo —— Kyoto —— Osaka`

或者经纬度、航线曲线、地图等高线这样的纹理，透明度控制在 **2–4%**。

用户基本不会主动注意到它，却会感觉页面“不空”。

---

## 3. 最大的布局调整：弱化左右栏，强化问卷主体

你目前实际上是：

**左导航 / 中问卷 / 右摘要**

这是典型的生产力软件布局。

对于需要连续回答 10 个步骤的旅行调查问卷，我更推荐：

**窄左栏 + 大中区 + 浮动摘要**

而不是三个视觉重量接近的栏。

桌面端可以变成：

```text
┌───────────────────────────────────────────────────────────────┐
│ ✦ Wanderly                  已自动保存       保存并稍后继续     │
├──────────┬──────────────────────────────────────┬───────────────┤
│          │                                      │               │
│ 01 ●     │       STEP 03 · 预算与取舍            │  旅行概览      │
│ 02 ✓     │                                      │               │
│ 03 ●     │       你希望这趟旅行                  │  京都 · 7天    │
│ 04       │       大概花多少钱？                  │  2人           │
│ 05       │                                      │               │
│ ...      │       [ ¥8,000 ]                     │  █████ 34%     │
│          │                                      │               │
│          │       ○ 舒适优先                      │               │
│          │       ○ 平衡预算与体验                │               │
│          │       ○ 尽量节省                      │               │
│          │                                      │               │
│          │         ← 上一步       继续 →         │               │
└──────────┴──────────────────────────────────────┴───────────────┘
```

比例我会使用：

```text
左侧       220px
主体       680–760px
右侧       260px
```

重点是让用户视线绝大部分时间停留在 **600–720px 宽度的问答区域**。

文字行太长，是长时间阅读最容易产生疲劳的原因之一。

---

## 4. 左侧 10 步导航需要“降噪”

现在左侧同时承担：

步骤、状态、完整度、说明、Legend。

信息稍微有点多。

用户答第 6 页时，其实最关心的只有：

> 我在哪里？
> 还有多久？
> 前面哪些已经完成？

所以新版左栏建议只保留：

```text
规划你的旅行

✓ 01 旅行轮廓
✓ 02 旅行人员
● 03 预算取舍
  04 旅行节奏
  05 路上怎么走
  06 住得更舒服
  07 吃好也玩好
  08 特别关照
  09 确认旅程

━━━━━━░░░
3 / 9
```

Legend 不要长期展示。

只有实际出现“必须满足”之类信息时，再就近显示。

这会明显降低认知负担。

---

## 5. 右栏不要一直像 Dashboard

你现在有：

* 信息完整度
* 当前步骤
* 14 个补充项
* 预算
* 天数
* 人数
* 步行
* 系统自动研究内容

从产品逻辑上都合理，但是**在填写问卷时一次展示太多**。

我会把右侧改成一张非常舒服的：

### 「你的旅行正在成形」

例如：

```text
YOUR JOURNEY

日本 · 京都
Oct 12 — Oct 19

7 天
2 人

预算
约 ¥18,000

旅行风格
慢节奏 · 美食 · 城市漫步

─────────
信息完成度

████████░░  68%

还剩 3 个部分
```

系统自动研究：

> 天气、签证、交通票制……

折叠到一个：

**我们会自动帮你准备 8 项信息  ›**

里面。

这样会有一种很重要的心理反馈：

> “我不是在填表，而是在把自己的旅行一点点搭出来。”

这是整个产品体验应该追求的核心。

---

## 6. 问题页面要建立稳定的阅读节奏

每一页最好维持完全一样的结构：

```text
STEP 04 · TRAVEL PACE

你的旅行，
想慢一点还是充实一点？

不用考虑得太精确，
选最接近你理想状态的即可。


        问题区域


← 返回                       继续 →
```

标题建议控制：

**30–36px / 1.3**

正文：

**15–16px / 1.75**

选项文字：

**16px / 1.5**

正文颜色千万不要 `#000`。

使用类似：

```css
color: #28332F;
```

次级说明：

```css
color: #77807A;
```

长时间看会舒服很多。

---

## 7. 字体可以成为新版非常漂亮的一部分

你附件里本来就加载了：

* Noto Sans SC
* Noto Serif SC
* Inter

因此我会直接利用，而不是再引入字体。

建议：

**问题标题：Noto Serif SC**

比如：

> 你希望这趟旅行，
> 留下怎样的感觉？

使用 Serif 会产生一点旅行杂志、生活方式品牌的感觉。

而：

按钮、选项、表单、导航、数字

全部继续使用：

**Noto Sans SC + Inter**

于是整个产品就会同时拥有：

> 情绪感 + 功能性

而不是整页都像 SaaS。

---

## 8. 第 0 页其实非常值得保留，但要进一步杂志化

你现在四个入口：

* 还没想好去哪
* 假期有了，去哪好呢
* 有想去的地方，时间待定
* 都定了，开始规划吧

这个设计逻辑很好。附件里这四张卡已经根据“目的地是否确定 / 时间是否确定”划分用户状态，并且每张配有不同主题插画。

但新版我会把它做得更像 **Travel editorial cards**。

不要四张卡都充满文字。

例如：

```text
┌─────────────────────────────┐
│                             │
│         [柔和插画]           │
│                             │
│  JUST EXPLORING             │
│                             │
│  还没想好去哪                │
│                             │
│  有点想出去走走。            │
│  先看看有哪些可能。          │
│                             │
│  从灵感开始              →   │
└─────────────────────────────┘
```

卡片：

```css
border-radius: 24px;
border: 1px solid rgba(...);
box-shadow: 0 8px 30px rgba(44, 52, 48, .06);
```

Hover 只：

```css
transform: translateY(-3px);
```

不要夸张动画。

---

## 9. Question Card 不应该每题都“套一个大白框”

这是我特别建议你改的一点。

很多网页问卷会变成：

```text
大背景
  ↓
大白色框
  ↓
标题
  ↓
又一个白色框
  ↓
选项
```

层层 Card 会产生很强的 UI 疲劳。

应该更多使用**留白建立层级**：

```text
问题

你希望每天安排多少活动？


○ 轻松一点
  每天 1–2 个主要安排

○ 刚刚好
  上午 / 下午各有安排

○ 尽量多体验
  希望充分利用时间
```

只有选项本身做轻微 Surface。

整个体验会安静很多。

---

## 10. Selected 状态一定要舒服，而不是“强提醒”

例如正常：

```text
┌────────────────────────┐
│ ○  慢一点              │
│    留更多自由时间       │
└────────────────────────┘
```

选择后：

```text
╭────────────────────────╮
│ ●  慢一点              │
│    留更多自由时间       │
╰────────────────────────╯
```

背景：

`#E8F0EB`

Border：

`#789887`

而不是高饱和主色整块填满。

因为用户会连续选择几十次，高饱和反馈很容易视觉疲劳。

---

## 11. Progress 也应该“情绪化”，不要一直强调百分比

现在是：

> 旅行画像完整度 0%

功能没问题，但偏系统语言。

可以改成：

```text
你的旅行正在成形

━━━━━━━────

已经完成 4 / 9 个部分
```

到后期：

> 已经很接近你的理想旅程了

比反复显示：

> 68%

更符合旅行规划的产品气质。

百分比仍然可以保留，但作为辅助信息。

---

## 12. 每 2～3 页给用户一个“喘息页”

这个对“长时间填写舒服”非常有效。

比如用户完成：

目的地
人员
预算

不要马上继续第五十个问题。

可以出现：

```text
✦

已经有点像一趟真正的旅行了。

京都 · 7天 · 两个人

你偏向慢节奏旅行，
住宿更看重位置，
预算主要留给餐饮与体验。

继续完善 →
```

只停留几秒或由用户点击继续。

这种页面不是没用的信息。

它负责降低**问卷疲劳感**。

---

## 13. 动效原则：慢、轻、短

建议：

页面进入：

`opacity 0 → 1`
`translateY(8px → 0)`

时间：

**180–240ms**

卡片 Hover：

**160ms**

Progress：

**400–600ms**

不要：

* 大幅 slide
* bounce
* 旋转
* 强 spring
* 每页不同动画

长流程产品里，稳定感比炫技重要。

---

## 14. 移动端不要保留桌面三栏思维

Mobile 推荐：

```text
✦ 自由行规划器           3/9

━━━━━━━────


03
预算与取舍

你希望这趟旅行
大概花多少钱？

...

[选项]



← 上一步       继续 →
```

顶部进度条固定。

底部导航 sticky。

旅行摘要变成：

> 查看我的旅行 ›

打开 Bottom Sheet。

不要让用户在手机上同时看到步骤、问卷和进度。

---

# 最终视觉风格

如果让我给这个新版几个关键词，我会选择：

**自然 / 安静 / 温暖 / 编辑感 / 轻旅行 / 高级但不奢华**

而不是：

**科技 / AI / Dashboard / SaaS / 高效率**

虽然背后确实是智能规划系统，但用户在填写阶段并不需要不断感觉：

> “我正在操作一个 AI 系统。”

更好的感受应该是：

> **“有人正在陪我，把一趟旅行慢慢想清楚。”**

你当前 HTML 的产品结构已经不用大改；真正能让体验提升一个档次的，是重新建立 **视觉主次、阅读宽度、色彩刺激度、问答节奏和阶段反馈**。尤其建议保留现在四种旅行起点以及 10 步流程，只重新设计它们的视觉表现和信息密度。

如果按这个方向实际落地，我会把首页从目前偏「**旅行规划后台**」的视觉，改成更接近 **Airbnb × Notion × Kinfolk 旅行杂志**之间的感觉：Notion 的安静易读、Airbnb 的亲和交互，再加一点旅行杂志式的 Serif 标题和自然配色。
