针对你这个**旅行方案规划器＋多步骤表单＋条件标签**的页面，建议优先研究“任务型交互”，而不是只看视觉炫酷的网站。下面这些案例最有参考价值。

## 一、最值得参考的产品网站

### 1. Airbnb：旅行产品整体体验

**网址：** https://www.airbnb.com/

适合参考：

- 目的地、日期、人数的渐进式选择
- 地图与列表联动
- 筛选条件的标签化展示
- 卡片 Hover、收藏与选中反馈
- 图片、价格和关键参数的信息层级
- 移动端底部操作栏

对你的页面最有价值的是：  
**将复杂规划过程包装成轻松、生活化的旅行体验。**

可以借鉴：

```text
选择条件 → 生成胶囊标签 → 即时更新摘要 → 随时撤销
```

不建议照搬其大量图片布局，因为你的页面更偏“旅行规划工具”。

## 二、交互系统方面的标杆

### 7. Linear：表单效率和即时反馈

**网址：** https://linear.app/

适合参考：

- 快速、克制的微动效
- 键盘操作
- 命令面板
- 菜单和弹窗的出现方式
- 选中、Hover、Focus 的状态一致性
- 乐观更新和撤销操作

虽然 Linear 不是旅行网站，但特别适合用来提升你的规划工具质感。

建议借鉴：

- 动效时长控制在约 `120–200ms`
- 卡片 Hover 只改变边框、背景和轻微位移
- 状态切换立即反馈
- 删除条件后提供 Toast 撤销
- 页面能用 Tab 和方向键完整操作
- 避免每次选择都打开确认弹窗

例如，条件状态可以这样操作：

```text
住宿品质  [♡ 偏好] [★ 必须] [× 不要]
```

选择“必须”后：

- 五角星由描边变为实心
- 背景从浅绿过渡到自然绿
- 右侧摘要同步新增条件
- 出现短暂提示：“已设为必须 · 撤销”
- 全过程不刷新页面、不跳动布局

## 五、针对当前页面推荐的交互设计

### 1. 三态条件选择

每个旅行条件右侧提供互斥选择：

```text
住宿品质    [♡ 偏好] [★ 必须] [× 不要]
```

- Hover：显示浅色背景
- 选中：实色背景、白色图标和文字
- 必须：绿色实心五角星
- 偏好：蓝色爱心
- 不要：珊瑚红叉号
- 被排除的**具体条件文字**增加删除线
- “不要”按钮文字本身不增加删除线

如果再次点击当前状态，可以恢复为未设置；也可以提供“清除状态”入口。

### 2. 右侧摘要即时同步

选择状态后，右侧条件列表通过轻微淡入和位移动画更新：

```text
必须满足
★ 住宿品质

优先满足
♡ 本地美食

明确不要
× 交通便利
```

其中“交通便利”增加删除线，但仍保持足够对比度。

### 3. 提供撤销，而不是确认弹窗

删除或改变条件时：

```text
已将“交通便利”设为不要    [撤销]
```

提示停留约 4～6 秒，不打断操作。

### 4. 路线类型加入预览反馈

Hover“中心辐射”“环线自驾”等选项时：

- 图标轻微动画
- 显示简短解释
- 出现淡化的路线示意
- 选中后同步更新预计步行、交通和预算

### 5. 生成方案需要明确过程反馈

点击“生成旅行方案”后，避免只显示旋转 Loading。可以显示阶段化进度：

```text
✓ 正在整理旅行条件
✓ 正在匹配目的地与景点
● 正在优化每日路线
○ 正在估算预算
```

同时保留已填写内容，不要让页面突然清空或完全被遮挡。

## 推荐优先体验顺序

如果时间有限，建议依次体验：

1. **Wanderlog**：与你的行程规划功能最接近  
2. **Airbnb**：学习旅行产品的整体氛围  
3. **Google Maps**：学习路线和地图联动  
4. **Linear**：学习高效、克制的交互反馈  
5. **Stripe**：学习复杂表单与状态设计  
6. **Mobbin / Page Flows**：查找具体流程参考  

对于当前概念图，最值得落地的不是复杂 3D 或滚动特效，而是：**即时同步、状态明确、可撤销操作、路线预览、渐进式展示，以及稳定流畅的微交互。**
