四、状态组件设计
--------------------------------------------------

将“偏好、必须、不要”实现为统一、可复用的状态组件，例如：

PreferenceTag
ConditionStatusChip
RequirementBadge

具体名称请遵循项目现有命名规范。

组件至少支持以下语义化属性：

- status: "preferred" | "required" | "excluded"
- selected: boolean
- disabled: boolean
- removable: boolean
- onClick
- onRemove
- size: "sm" | "md"

不要让调用方直接传入任意颜色来决定业务状态，状态颜色应由组件内部语义映射。

1. 偏好 Preferred

- 图标：爱心轮廓
- 中文：偏好
- 主色：#3478F6
- 浅色背景：#EEF5FF
- 边框：#A9C8FF
- 选中状态：蓝色实心背景，白色图标和文字

2. 必须 Required

- 图标：实心五角星
- 中文：必须
- 主色：#159A72
- 浅色背景：#EAF8F3
- 边框：#8ED8BE
- 选中状态：绿色实心背景，白色五角星和白色文字

五角星表达“必去、不可错过、必须满足”。必须同时保留“必须”文字，不能只显示图标，避免被误解为收藏或评分。

3. 不要 Excluded

- 图标：叉号
- 中文：不要
- 主色：#E65D65
- 浅色背景：#FFF0F1
- 边框：#F2ADB2
- 选中状态：珊瑚红实心背景，白色图标和文字，文字带删除线

4. 交互状态

每个状态组件都要实现：
- Default
- Hover
- Active
- Selected
- Keyboard focus
- Disabled

Focus 状态必须有清晰的焦点环，但不能改变组件尺寸造成布局跳动。

推荐效果：

[♡ 偏好]  [★ 必须]  [× 不要]

图标与文字之间保持 4px～6px 间距。

5. 右侧摘要同步

“我的旅行条件”列表必须使用同一套语义：

- 必须满足：绿色五角星
- 优先满足：蓝色爱心
- 明确不要：珊瑚红叉号

如果列表项支持删除：
- 删除按钮必须有 aria-label
- Hover 时显示明确反馈
- 点击删除不能误触整个列表项
- 删除后的状态更新必须继续使用现有业务逻辑

六、响应式要求
--------------------------------------------------

优先沿用项目已有断点。如果当前没有完善的响应式规则，则采用以下策略：

1. 大屏，宽度 ≥ 1200px
   - 保持左、中、右三栏
   - 中间内容区域自适应
   - 左右侧栏宽度稳定
   - 右侧摘要可 sticky

2. 中屏，768px～1199px
   - 左侧步骤栏可以缩窄或折叠
   - 主内容优先占据可用空间
   - 右侧摘要移动到主表单下方，或按照现有产品逻辑折叠
   - 不允许水平滚动

3. 小屏，< 768px
   - 单栏布局
   - 状态按钮允许合理换行
   - 主操作按钮接近全宽
   - 表单字段垂直排列
   - 不得缩小到难以点击或阅读
   - 保证最小触控目标约 44 × 44px

本任务重点仍是桌面端效果，不要为了移动端重构全部页面。

--------------------------------------------------
七、无障碍要求
--------------------------------------------------

1. 不得仅依赖颜色传达“偏好、必须、不要”。
2. 始终组合使用：
   - 图标
   - 文本
   - 颜色
3. 可点击状态组件应使用 button 或项目中等价的可访问组件。
4. 互斥状态使用 aria-pressed、radio group 或与真实行为一致的 ARIA 语义。
5. 图标如果只是装饰，设置 aria-hidden="true"。
6. 图标按钮必须提供 aria-label。
7. 确保键盘可以完成所有选择、移除和提交操作。
8. Focus 样式清晰可见。
9. 正文和关键交互文字应满足 WCAG AA 对比度要求。
10. 不要通过去掉 outline 破坏键盘焦点可见性。
