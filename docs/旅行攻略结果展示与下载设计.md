# 旅行攻略结果展示与下载设计

> 状态：已实施
> 更新时间：2026-08-30
> 适用范围：旅行攻略生成完成后的前端结果页、后端导出、浏览器下载与服务端产物保存

## 1. 设计结论

旅行攻略结果分成两条链路，但必须共享同一份计划版本、模板和展示数据：

1. **前端展示链路**：前端读取结构化 Presentation ViewModel，用 React/HTML 展示攻略总览和每日攻略。
2. **文件保存链路**：后端通过内部渲染页和 render-worker 异步生成 PNG/PDF，前端只负责创建导出任务、展示进度和触发下载。

```text
生成任务
  ↓
计划内容可读（plan_readable）
  ↓
展示数据可用（page_viewable） ──────→ 前端结果页
                                           │
                                           └→ 创建导出 → 后端渲染 → 预签名 URL → 下载到设备
```

禁止使用前端 DOM 截图、Canvas 拼图或 `window.print()` 作为正式导出方案。正式下载文件必须由后端渲染，以保证字体、图片、页面尺寸和 PDF 分页稳定。

## 2. 核心一致性约束

用户在浏览器中看到的结果与下载文件必须绑定以下四项：

```text
plan_version_id
+ template_id
+ Presentation ViewModel
+ 已解析的图片资源版本
```

Presentation 接口已经返回 `plan_version_id` 和最终解析后的 `template_id`。结果页首次成功加载后应固定这两个值：

- 后续读取单日 Presentation 时携带同一个 `plan_version_id`；
- 创建导出任务时携带同一个 `plan_version_id` 和 `template_id`；
- 不在前端硬编码默认模板，也不把历史模板 ID 当作当前模板；
- 若导出返回 `EXPORT_PLAN_VERSION_MISMATCH`，提示“攻略内容已经更新，请刷新页面后重新下载”，不得静默导出最新版本。

页面外壳可以响应式布局；成品预览区域应复用对应模板组件和 ViewModel。模板画布在窄屏上整体缩放，不通过重新排版改变成品的换行和分页。若需要更强的移动端可读性，可另设“阅读模式”，但阅读模式不作为导出预览。

## 3. 前端结果页设计

结果页路由沿用：

```text
/plans/{planId}
```

### 3.1 页面结构

结果页由以下区域组成：

#### 顶部信息区

- 返回计划列表；
- 目的地、起止日期、总天数；
- 当前模板；
- 生成状态或最近更新时间；
- 非阻断降级提示；
- 主操作“下载攻略”。

当 Presentation 的 `validation_status` 为 `DEGRADED`，显示轻量提示，例如“部分图片暂不可用，已使用备用素材”，但不阻止用户阅读或下载已有产物。

#### 攻略总览

默认选中“攻略总览”，展示完整计划 ViewModel，必须包含：

- Hero 图；
- 行程标题和简介；
- 总体路线；
- 每日摘要；
- 住宿、交通、美食和预算汇总；
- 重要提醒；
- 完整的每日攻略合集。

数据来源：

```http
GET /api/v1/travel-plans/{plan_id}/presentations/full
    ?plan_version_id={plan_version_id}
```

`full` 接口一次返回攻略总览和全部天数，不应在进入结果页时并发请求所有单日接口。

#### 每日攻略

提供“攻略总览、Day 1、Day 2……”导航。桌面端可以使用侧边导航，移动端使用横向日期标签或下拉选择。

每日页必须包含：

- 当日 Hero/主题图；
- 日期、城市和当日主题；
- 时间轴与景点安排；
- 餐饮、交通、地址及注意事项；
- 当日预算；
- “下载当天”操作。

需要单日独立加载时调用：

```http
GET /api/v1/travel-plans/{plan_id}/presentations/{day_number}
    ?plan_version_id={plan_version_id}
```

### 3.2 页面状态

前端状态流转为：

```text
generating
→ plan_readable
→ page_viewable
→ viewing
→ exporting
→ downloadable
```

- `plan_readable=true`：允许先展示计划文字内容；
- `page_viewable=true`：加载最终 Presentation；
- 导出是独立后台任务，不阻塞结果页浏览；
- 导出完成后显示通知，并在下载面板中展示文件；
- 页面刷新后应能根据服务端数据恢复结果，而不是依赖内存中的 ViewModel。

轮询生成任务时直接使用后端返回的 `progress`、`message`、`warnings` 和 `milestones`，前端不得自行推算生成进度。

### 3.3 缓存键与本地数据

前端查询缓存至少包含：

```text
plan_id + plan_version_id + template_id + page_type + day_number
```

浏览器本地只保存恢复页面所需的 ID、当前页签和非敏感 UI 状态。完整私人行程、下载 URL 和鉴权信息不得持久化到 `localStorage`。

## 4. 下载面板设计

“下载攻略”打开弹窗或移动端底部面板。推荐提供以下导出预设：

| 用户选项                 | `format`       | `scope`      | `day_numbers`  | 当前产物               |
| ------------------------ | -------------- | ------------ | -------------- | ---------------------- |
| 完整攻略 PDF（默认推荐） | `PDF`          | `FULL_PLAN`  | `null`         | 1 个多页 PDF           |
| 完整攻略长图             | `PNG`          | `FULL_PLAN`  | `null`         | 1 个整页 PNG           |
| 每日攻略合集 PDF         | `PDF`          | `ALL_DAYS`   | `null`         | 1 个按天排序的多页 PDF |
| 全部每日攻略 PNG         | `PNG`          | `ALL_DAYS`   | `null`         | 每天 1 个 PNG          |
| 当前某一天               | `PNG` 或 `PDF` | `SINGLE_DAY` | `[day_number]` | 1 个单日文件           |

创建导出任务：

```http
POST /api/v1/travel-plans/{plan_id}/exports
Content-Type: application/json
```

```json
{
  "format": "PDF",
  "scope": "FULL_PLAN",
  "day_numbers": null,
  "template_id": "ink_paper_v1",
  "plan_version_id": "0198..."
}
```

相同的版本、格式、范围、天号和模板构成同一个导出意图。后端已经实现幂等复用；前端重试时不得故意改变这些字段来绕开幂等。

## 5. 导出任务与交互

创建成功后轮询：

```http
GET /api/v1/exports/{export_id}
```

导出状态为：

| 状态        | 前端行为                                              |
| ----------- | ----------------------------------------------------- |
| `QUEUED`    | 显示“等待导出”，允许关闭面板继续浏览                  |
| `RENDERING` | 显示服务端 `progress`，禁用重复创建按钮               |
| `COMPLETED` | 展示全部文件和下载按钮                                |
| `PARTIAL`   | 展示成功文件，同时明确提示哪些文件未生成              |
| `FAILED`    | 展示后端错误文案；仅在 `retryable` 语义允许时提供重试 |

导出过程中不锁定结果页。用户关闭下载面板后任务继续运行，完成时使用 Toast 或站内通知提示。

`files[]` 至少展示格式、对应天号和 `byte_size`。不向用户展示对象存储键或内部渲染地址。

## 6. 浏览器下载流程

预签名 URL 有效期为 7 天，只是临时访问凭证，不是文件永久地址。前端不得把 `files[].url` 长期缓存到数据库或 `localStorage`。

用户每次点击下载时执行：

1. 再次调用 `GET /api/v1/exports/{export_id}`；
2. 获取重新签名后的最新 `files[].url`；
3. 立即触发浏览器下载；
4. URL 过期时重新获取导出详情，不重新渲染文件。

大文件优先使用浏览器直接导航到预签名 URL，避免先下载为 Blob 后占用两份浏览器内存。对象存储响应需要设置 `Content-Disposition: attachment`。

`PNG + ALL_DAYS` 返回逐日 PNG，并额外返回一个 ZIP 合集。界面以 ZIP 作为“一键下载全部”入口，同时保留逐日文件列表；禁止自动触发 N 次下载。

## 7. 下载文件名规范

### 7.1 强制规则

下载文件名不得直接包含中文，中文信息统一转为不带声调的完整拼音。

- 仅允许小写 ASCII 字母 `a-z`、数字 `0-9`、连字符 `-`、下划线 `_` 和扩展名分隔点；
- 汉字转为无声调拼音；
- 空格、斜杠、标点和其他特殊字符统一替换为 `-`；
- 连续连字符合并，移除首尾连字符；
- 天号固定补两位，例如 `day-01`；
- 文件名由后端统一生成，前端不得自行翻译或拼接；
- 结果为空时使用 `travel-plan` 作为兜底；
- 最终文件名建议不超过 120 个字符，超长时优先截断目的地部分，保留日期、范围、版本和扩展名；
- 多音字和行政区重名必须使用服务端固定映射，保证同一计划重复导出得到相同文件名。

### 7.2 命名结构

```text
{destination-pinyin}-{date-range}-{scope}-v{version}.{ext}
```

推荐的 `scope` 拼音标识：

| 内容         | 文件名标识         |
| ------------ | ------------------ |
| 完整攻略     | `wanzheng-gonglue` |
| 每日攻略合集 | `meiri-gonglue`    |
| 单日攻略     | `day-{NN}`         |

示例：

```text
chengdu-2026-10-01_2026-10-03-wanzheng-gonglue-v3.pdf
chengdu-2026-10-01_2026-10-03-wanzheng-gonglue-v3.png
chengdu-2026-10-01_2026-10-03-meiri-gonglue-v3.pdf
chengdu-2026-10-01-day-01-v3.png
chaoyang-beijing-2026-10-01-day-01-v2.pdf
```

下载响应示例：

```http
Content-Type: application/pdf
Content-Disposition: attachment; filename="chengdu-2026-10-01_2026-10-03-wanzheng-gonglue-v3.pdf"
```

对象存储内部的 `storage_key` 可以继续使用 `full-plan.pdf`、`day-01.png` 等稳定技术名称；用户可见文件名通过预签名下载响应的 `Content-Disposition` 设置，两者不要求相同。

建议在 `files[]` 中补充 `file_name` 字段，便于前端在下载列表中提前展示最终名称：

```json
{
  "format": "PDF",
  "day_number": null,
  "file_name": "chengdu-2026-10-01_2026-10-03-wanzheng-gonglue-v3.pdf",
  "url": "https://...",
  "byte_size": 1234567,
  "expires_at": "2026-09-06T10:00:00.000Z"
}
```

## 8. “保存”语义

产品文案必须区分两种操作，禁止只使用含义不清的“保存”：

- **收藏到账号**：计划及其版本保留在服务端，可从计划历史中再次打开；
- **下载到设备**：将当前版本的 PNG、PDF 或未来的 ZIP 保存为本地文件。

下载文件是某个版本的不可变快照。本地文件下载成功后不受预签名 URL 到期和服务端导出物清理影响。

服务端导出对象按现有存储策略保留 90 天；预签名 URL 有效期为 7 天。计划源数据与可再生成的导出文件是不同的保留对象，前端不得把“链接过期”描述为“攻略已删除”。

## 9. 权限与安全边界

- 所有计划、Presentation 和导出查询都必须校验当前用户归属；不存在与越权统一返回 404；
- 导出桶保持私有，只通过短期预签名 URL 下载；
- `/render/**` 是 render-worker 使用的内部 HTML 页面，对公网必须返回 404；
- 前端不得嵌入、跳转或暴露 `/render/**`；
- API 只负责读取导出记录和签发下载地址，只有 render-worker 可以写入导出桶；
- 日志不得记录完整预签名 URL、Cookie、完整私人行程或下载内容；
- 分享下载文件时可提示文件可能包含住宿、日程和预算等私人信息。

## 10. 无障碍与移动端要求

- 日期导航支持键盘操作并提供正确的 ARIA 选中状态；
- Hero 和内容图片使用 ViewModel 中的替代文本，降级图片也需要可理解的说明；
- 导出进度和完成提示使用 `aria-live`；
- 状态不能只依赖颜色表达；
- 移动端下载面板使用底部抽屉，下载按钮触控区域不小于 44 × 44 CSS px；
- 长图预览按容器宽度缩放，不在移动端一次解码多个全尺寸 PNG；
- 结果展示使用 HTML/ViewModel，不把 PNG 当作唯一阅读载体。

## 11. 当前能力与待补充能力

### 11.1 当前已具备

- 生成任务状态和 `plan_readable/page_viewable` 里程碑；
- 完整计划及单日 Presentation 公网接口；
- Presentation 返回 `plan_version_id`、`template_id` 和 `validation_status`；
- `PNG/PDF × FULL_PLAN/ALL_DAYS/SINGLE_DAY` 导出组合；
- 导出任务幂等、状态轮询和错误返回；
- 完成文件预签名及过期后重签；
- PNG 每日多文件和 PDF 多页合并；
- 内部渲染路由的 HMAC 与网络隔离。

### 11.2 已补充

1. **拼音下载文件名**：后端统一生成纯 ASCII 拼音文件名，预签名 GET 响应设置 `Content-Disposition`；
2. **导出文件名字段**：`ExportFile` 已增加 `file_name`，前端类型和接口文档同步；
3. **导出历史接口**：`GET /api/v1/travel-plans/{plan_id}/exports` 可恢复进行中和已完成的导出；
4. **全部每日 PNG 的 ZIP**：`PNG + ALL_DAYS` 在逐日 PNG 之外附加 ZIP 合集；
5. **文档状态统一**：导出终态统一为 `COMPLETED/PARTIAL/FAILED`；
6. **结果页成品预览**：公网页面复用模板注册表和 Presentation ViewModel，并提供总览、每日攻略和下载导航。

## 12. 验收清单

- [ ] 结果页包含 Hero 图、攻略总览和全部每日攻略；
- [ ] 桌面端和移动端都能切换总览与每日内容；
- [ ] 前端展示和导出请求使用相同的 `plan_version_id` 与 `template_id`；
- [ ] 版本变化时阻止导出并引导刷新；
- [ ] 导出期间仍可继续浏览结果页；
- [ ] `COMPLETED`、`PARTIAL` 和 `FAILED` 都有明确界面；
- [ ] 下载前重新获取预签名 URL，链接过期不会触发重新渲染；
- [ ] 完整攻略 PNG 是 PNG 格式，完整攻略 PDF 是有效多页 PDF；
- [ ] 每日 PDF 按 `day_number` 升序合并；
- [ ] 多个每日 PNG 不被浏览器自动批量弹窗拦截；
- [ ] 所有用户可见下载文件名均为无声调拼音/ASCII，不直接包含中文；
- [ ] 文件名在 Windows、macOS、Linux 和主流浏览器中可保存；
- [ ] 下载响应带 `Content-Disposition: attachment`；
- [ ] `/render/**` 对公网不可访问；
- [ ] 无权用户无法读取其他用户的计划、Presentation 或导出文件；
- [ ] 图片降级时仍可展示和导出，并向用户说明降级状态。
