```text

├─ /                        需求采集工作台（Planner V2.1 九步问卷 + 三栏布局）
```

**双数据源分段交付**（21.2 措施一，T1→T2）：

1. 先试 `getFullPresentation`（13.4，落库 ViewModel，含 Hero/配图/路线图）—— 404 是正常时序（编排未完成），不报错；

4. 模板组件由 `viewModel.template_id` 经 [templates/registry.ts](../../apps/web/src/templates/registry.ts) 选取；未注册的套件显示提示而不是静默回退；

6. 只有 `source === 'presentation'` 时才渲染 `ExportPanel`（文字版没有可导出的版本锚点）。

**ExportPanel** 支持六种导出（`buildExportRequest` 组装）：完整 PDF、完整长图、每日合集 PDF、全部 PNG(含 ZIP)、单日 PNG、单日 PDF。轮询间隔 2s、上限 120s；刷新页面时用 `listExports` 恢复未完成的导出任务（按 `plan_version_id + template_id` 匹配）。下载前重新 `getExport` 拿新签名 URL 再 `window.location.assign`。

## 2. Planner V2.1 九步问卷逐步实现

九步**共用一个 `StepPage` 组件**，差异只有两样：区块小标题（[steps/sections.ts](../../apps/web/src/components/planner/steps/sections.ts) 的 `STEP_SECTIONS` 表）与步骤级 `slots` 注入。步骤元数据（nav/title/intro）来自契约 `PLANNER_STEPS`（[packages/schemas/src/planner-fields.ts:228](../../packages/schemas/src/planner-fields.ts#L228)）。

`STEP_SECTIONS` 每步只声明「组名 + 字段 ID 列表 + 图标 + layoutGroup」，渲染顺序 = `PLANNER_FIELDS` 数组顺序（`sections.test.ts` 断言两者逐个相等，防止漂移）。

> 字段总数 76（PV2-01-001 ~ PV2-10-006），每一步的字段清单见下表；`⚙` 表示该字段由**组合控件/slot** 承载而非常规描述符渲染。

## 3. 支撑机制（状态机与数据流）

### 3.1 状态模型

- 状态定义：[lib/planner/state.ts](../../apps/web/src/lib/planner/state.ts)
  - `PlannerState = { answers, touched, optIns, activeStep, templateId, devMode }`
  - `answers` 形状与契约 `planner_profile` **逐字相同**（嵌套块，提交时几乎直接发出）；`readAnswer(answers, apiKey)` 按 `块.键` 读取；
  - `templateId` 刻意**不在** answers 里（它走 `output_preferences` 而非 `planner_profile`）；
  - reducer 六个 action：`answer`（块级浅合并 + touched 记账）/ `toggleOptIn`（收起不清值）/ `goToStep` / `setTemplate` / `setDevMode` / `restore` / `reset`；
  - `hasValue` 按五种包装形状判空（`{enabled}` / `{user_reported}` / `{values, other_text}` / 数组 / 普通对象）；`EXPLICIT_EMPTY_FIELDS` 四个字段用空数组表达用户明确选了「无」。

### 3.2 三层状态派生（规范 5）

- Field State 七态：[lib/planner/field-state.ts](../../apps/web/src/lib/planner/field-state.ts) —— `hidden`/`inactive`（值保留）/`unanswered`/`answered`/`invalid`/`verify_pending`/`verified`（本轮永不出现）。VERIFY 两级都落 `verify_pending`，不阻塞生成。
- Step State 四态 + Trip State 五态：[lib/planner/step-state.ts](../../apps/web/src/lib/planner/step-state.ts) —— `buildSnapshot` 一次算好供左栏/右栏/按钮共用（防「左栏说完成、按钮说缺项」）。**每次都从 Field State 重算**，不按浏览历史（上游回改能正确回退状态）。完整度 = 已回答已触发字段 / 已触发字段，**不加权**。
- `computeTripState` 顺序：`plan-generated` → `draft`（一个字段没碰）→ `blocked`（有 blockers 或授权未勾）→ `research-needed`（有待核验）→ `ready-for-plan`。
- 生成按钮文案 `generateButtonLabel` 按 Trip State 出五套；`blocked`/`draft` 时按钮**可点**并跳到第 9 步问题清单（规范 18 反对纯 disabled）。

### 3.3 条件触发引擎（规范 6，附录 B 的 D-01~D-08）

- 文件：[lib/planner/triggers.ts](../../apps/web/src/lib/planner/triggers.ts)
- 一张 `TRIGGERS` 表只写非恒显字段 + `ALWAYS_VISIBLE_DESPITE_TRIGGER` 白名单（六个字段的 trigger 文本是排序/必填说明而非显示条件）；`triggers.test.ts` 反向断言完整性。
- `buildTriggerContext` 一次算好 24 个派生值（hasMinor/hasChild/isMultiCity/isInternational/involvesAir…），跨境判定要求**出发国与目的国都已知且不同**（误触发会让国内游用户被问护照，漏触发会让跨境用户没查签证）。
- `unresolvedBlockers` 用后台下发的 `field_requirements`（BASE/CONDITIONAL_REQUIRED + trigger_code 激活判定），与页面「必填项」徽标同一份清单，避免显示与生成逻辑分叉。
- `TRIGGER_REASON`：条件字段首次展开时的「为什么问你这个」。

### 3.4 字段渲染管线

```text
StepPage（按 sections 分组）
  └─ FieldControl（容器：标题/必填徽标/触发原因/错误/DevBadge，data-field 挂这层）
       └─ FieldBody：slot（第9步）→ toggle 开关 → parts[]
            └─ PartField → PrimitiveControl（switch 分派 22 种原语）
                 ├─ ChoiceControls：ChoiceRow / CheckGroup / RankSelect
                 ├─ ValueControls：Counter / Number / RangeSlider / Money(Range) / Time / DualTime / Date(Range) / Text(Area/List) / BoolSwitch
                 ├─ PlaceControls：PlaceSelector（二级弹层）/ PlaceList / DestinationList
                 └─ ObjectList（七处 Repeater 共用一个实现；follow_count 行数跟计数器；index_key 删除后重排）
```

- 描述符表：[lib/planner/descriptors.ts](../../apps/web/src/lib/planner/descriptors.ts)（`Record<PlannerFieldId, FieldDescriptor>`，少一个键是编译错误；描述**值的形状**而非视觉）
- 值读写：[lib/planner/field-io.ts](../../apps/web/src/lib/planner/field-io.ts)（`patchPart`/`patchToggle`/`truncated` 等；计数器变小时**第二个 action** 截断跟随数组，不合并以保持 touched 归属）
- 选项解析：配置中心优先、内置回退，见 [PlannerConfigProvider.tsx](../../apps/web/src/components/planner/PlannerConfigProvider.tsx) 的 `usePlannerOptionResolver`（ENUM 取交集、CONDITION_CODE 允许新码；配置里下线但草稿里还留着的条件码显示「已下线」提示并可一键移除）

### 3.5 校验

- [lib/planner/validation.ts](../../apps/web/src/lib/planner/validation.ts)：只做**本地可判定**的规则（日期倒置、数量上限、Repeater 行缺关键键等），不重复实现服务端 N-01~N-12（两边重叠处口径必须一致）。错误显示在字段下方，`FieldControl` 上挂 `planner-field--invalid`。

### 3.6 草稿持久化（规范 6）

- [lib/planner/persistence.ts](../../apps/web/src/lib/planner/persistence.ts)：localStorage 键 `tps.planner.v2.draft`，`DRAFT_VERSION = 2`（v1→v2 定向迁移剔除已退役的 `destination_status: 'UNDECIDED'`）；
- 防抖 600ms（`AUTOSAVE_DEBOUNCE_MS`，滑块一次交互几十次变更，逐次写会发涩）；首帧不写（`hydrated` ref 防空状态盖掉刚读出的草稿）；
- 恢复时不跑整份 schema 校验（一个枚举改名不应作废 70 个字段），但 `templateId` 要对当前 `TEMPLATE_ID_VALUES` 验一次（已退役套件回退 null）；
- 保存失败不阻断编辑但顶栏可点重试（`SAVE_STATE_LABEL` 四态）。

### 3.7 提交与生成轮询（规范 13.1/13.2/18）

- 请求构建：[lib/planner/request.ts](../../apps/web/src/lib/planner/request.ts) —— `buildPlannerRequest` 输出**两套东西**：`planner_profile`（逐字答案）+ 投影（`trip`/`travelers`/`budget`/`pace`/`conditions`，喂既有 P1~P8 链路）。投影有损处全部写注释（如 RESTAURANT/TRANSFER 订单类型无 P8 对应值）；`prepareProfile` 提交前剔空占位行、盖 `reported_on`/`acknowledged_at`；`included_items` 必须发（口径分叉教训见文件内注释）；`output_preferences` 仅在显式选了模板时发。
- 提交入口 `Planner.submit()`：`blocked`/`draft` 不发请求而是跳第 9 步；`submitting`/`generating` 期间弹层**不可关闭**（整个 submit 包 try/catch，防未捕获异常把用户困在弹层后）；每次提交换新 `client_request_id`（13.8 幂等）。
- 轮询：2s 间隔、320s 上限；`isPlanReadable`（[lib/generation-dialog.ts](../../apps/web/src/lib/generation-dialog.ts)）在 `milestones.plan_readable` 或进入保存后阶段时转 `ready`——文字版先放人走（T1），`setPlanId` 同时打开第 10 步。
- 弹层视图由纯函数 `dialogViewFor` 推导（两行文案分工：「在做什么」用后端 message，「还要多久」用稳定文案；`percent` 三态：数字/跑马灯/不画；失败态按 `needsAuth`/`shortfallCr`/`retryable` 给不同的下一步建议）。

## 5. 样式体系

### 5.1 选项按钮尺寸标准（TP-9-01）

所有步骤页面的选项按钮（`.planner-choice`）必须统一使用以下尺寸标准：

| 属性 | 值 | 说明 |
|------|-----|------|
| `min-height` | `43px` | 最小高度，确保触控目标 |
| `padding` | `10px 15px` | 内边距 |
| `border-radius` | `12px` | 圆角 |
| `font-size` | `13px` | 字号 |

**实现位置**：`apps/web/src/app/planner.css` 中的全局 `.planner-choice` 规则。

**覆盖限制**：
- 步骤级覆盖（如 `[data-step='01']`、`[data-step='04']`）只允许调整**颜色、阴影、间距**等非尺寸属性
- **禁止**在步骤级覆盖中修改 `min-height`、`padding`、`border-radius`、`font-size`
- 按钮的**视觉风格**（边框样式、背景色、文字颜色、图标、选中态表现等）由各步骤**自由设计**，尺寸标准仅约束 `min-height` / `padding` / `border-radius` / `font-size` 四项
- 例外：`.planner-choices--compact` 变体用于标签云等高密度场景，由使用方显式声明，不受 43px 标准约束

**状态模型**：
- 选项按钮只有**要 / 不要**两个状态（选中 / 未选中）
- 选中态通过 `.planner-choice--on` 表达，样式由各步骤自由设计
- 无三态（偏好 / 必须 / 不要）循环逻辑

**历史变更**：
- 第 1 步原为唯一使用大尺寸按钮的步骤（`min-height: 43px`）
- 第 4 步曾使用小尺寸按钮（`min-height: 32px`），已废弃并统一为 43px 标准
- 三态标签（TriStateTag）已从采集问卷中移除，统一为两段式选择（要 / 不要）
