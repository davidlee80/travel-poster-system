# 测试、部署与运维

## 本地启动

### 只启动开发基础设施

```bash
pnpm install
copy env.example .env
pnpm infra:up
pnpm db:migrate
pnpm db:status
pnpm build
pnpm test
```

`infra:up` 只启动 PostgreSQL/pgvector、Redis 和 MinIO，不会启动 Web/API/Worker。

### 启动可在浏览器操作的完整栈

```bash
node tools/gen-local-env.mjs
pnpm mvp:build
pnpm mvp:up
```

浏览器必须访问 `http://localhost:8080`。Web 镜像中的 `NEXT_PUBLIC_API_BASE` 是空串，浏览器发同源 `/api/*`；8080 的 Nginx 才会把请求转给 API。直接打开 3000 只有 Next.js，没有 API 反代，所有业务请求都会 404。

停止使用 `pnpm mvp:down`。查看完整栈日志使用 `pnpm mvp:logs`。

### 离线页面快照

完整栈运行时执行 `pnpm preview`，生成 `preview/planner.html`、`legal.html`、`full.html` 和 `day1.html`。它用于评审静态页面，不支持登录、生成弹层等后端状态，不能替代 8080。

## 配置分组

完整键与说明以 [`env.example`](../../env.example) 和各包 `config.ts` 为准。理解配置时按以下分组查找：

| 分组          | 典型用途                                                | 读取代码                                                   |
| ------------- | ------------------------------------------------------- | ---------------------------------------------------------- |
| HTTP/运行时   | 端口、环境、日志、探针                                  | `shared/config.ts`、各 app `main.ts`                       |
| PostgreSQL    | `DATABASE_URL`、连接池                                  | `db/pool.ts`                                               |
| Redis/队列    | Redis URL、队列并发                                     | `queue/redis.ts`、Worker main                              |
| S3/MinIO      | 素材桶、导出桶、endpoint、region、凭据                  | `storage/config.ts`、`exports-storage.ts`                  |
| 身份          | session/render/internal key、Cookie、安全策略、匿名开关 | API main、`shared/identity/*`                              |
| 手机验证      | 发送模式、验证码 TTL/冷却                               | `api/identity/phone-verification.ts`                       |
| LLM/Embedding | fake/direct/gateway、base URL、key、model、timeout      | `llm/config.ts`                                            |
| 图片/搜索     | IMAGE/IMAGE_SEARCH mode、预算、Provider                 | `llm/image*.ts`、Worker assets                             |
| Feature flags | 生成、导出、匿名、百分比放量                            | `shared/feature-flags.ts`                                  |
| CR 计费       | 总开关、CR/人民币比率、注册赠送、预留缓冲、用量估算上限 | `billing/credits.ts`、`billing/estimate.ts`、三个 app main |
| Observability | Prometheus、OTLP、service name                          | `observability/otel-sdk.ts`                                |

生产密钥不得写进 Helm `values.yaml`，只通过 Secret 引用。API 的导出桶凭据只需要 `GetObject`/presign 能力；写权限只给 render-worker。

### 视觉测试的常见误区

`pnpm test:visual` 自己不渲染，只比较 `out-fixtures` 与基线。样式或模板变化后必须先执行：

```bash
pnpm fixture:render
pnpm test:visual
```

失配时先判断是否为回归；不要用 `visual:update` 把意外变化覆盖成新基线。基线只能在 Linux 容器生成，Windows 字体渲染不可作为生产基准。

## 40 项门禁怎样理解

机器可读清单在 [`tools/acceptance-gates.mjs`](../../tools/acceptance-gates.mjs)，报告器在 `tools/gate-report.mjs`。实施计划 P8 结束时口径为 40 项：

- 自动命令项：有依赖时执行；缺数据库的本机可能跳过集成项；
- CI-only：视觉、字体、Linux 十项、基线来源等必须在 Linux 环境判定；
- 人工：T1/T2 P95 与 Hero 真实命中率，需要真实模型和流量，不计退出码；
- “命令退出 0”不总等于测试真的执行，例如 Windows 上 SIGTERM 测试会跳过。

因此交付结论应同时报告通过、跳过、CI-only、人工与失败数量，不能只说 `pnpm gate` 是绿色。

## 可观测性

### 指标

机器目录是 [`packages/observability/src/catalog.ts`](../../packages/observability/src/catalog.ts)，各应用注册指标后由测试做双向漂移检查。主要观测域：

- 任务总量、状态、错误码、T1/T2 与各阶段耗时；
- LLM 请求时延、token、候选位置与故障转移；
- 规则违规、修复轮次、历史参考命中；
- 素材解析策略、评分、搜索结果、AI 调用、缓存命中；
- 渲染失败、降级、导出格式与结果；
- 身份事件、配额、功能开关拒绝；
- CR 闸门结果、结算/退款/坏账金额、未定价用量；
- 匿名清理与知识行数。

指标标签只能来自 [`ALLOWED_LABELS`](../../packages/observability/src/labels.ts)。禁止 `user_id/email/plan_id/trace_id` 等高基数标签。

### 日志与 Trace

[`packages/shared/src/logger.ts`](../../packages/shared/src/logger.ts) 在序列化层剥离 token、Cookie、email、IP、原始请求、`plan_json` 等。`created_ip` 只能进入单独安全审计 logger。业务日志用 `job_id/plan_version_id` 等定位，但不要把用户文本插入 message。

OpenTelemetry 在 HTTP、pg、Redis 与显式 span 之间串联；队列通过 [`trace-context.ts`](../../packages/queue/src/trace-context.ts) 注入/提取上下文。

## 探针与优雅停机

所有后端进程由 `runWorker`/Server 提供：

- `/healthz`：进程存活即 200；
- `/readyz`：依赖可用且未排空为 200，draining 时 503；
- `/metrics`：Prometheus 文本。

SIGTERM 后先停止接新请求/任务，等待在途工作，再逆序关闭队列、Redis、数据库和 tracing。容器用 tini 作为 PID 1。Render Worker 的 Chromium 子进程尤其依赖正确回收。

## 部署约束

- 生产唯一正确性基准是 Linux x86-64/glibc；
- 容器 UID 为 10001，禁止 root；
- `TZ=UTC`、`LANG=C.UTF-8` 并安装 tzdata；
- render-worker 至少 2Gi 内存，`/dev/shm` 1Gi，代码另有 `--disable-dev-shm-usage` 兜底；
- 系统字体装完整 Noto CJK，Web 只发 woff2 子集；
- pnpm 通过 `supportedArchitectures` 保留 Linux sharp 二进制，镜像不拷本地 `node_modules`；
- 路径大小写、分隔符、LF 与可执行位由 CI/ESLint/Prettier 护栏。

## 排障入口

详细步骤见 [运维手册](../运维手册.md)。快速定位：

| 现象                       | 先查                                                                   |
| -------------------------- | ---------------------------------------------------------------------- |
| 页面 API 全 404            | 是否打开 8080 而不是 3000；Nginx 反代                                  |
| 任务长期 QUEUED            | Redis/Worker readiness、队列等待、`JOB_QUEUE_TIMEOUT`                  |
| T1 慢                      | LLM 时延/候选位置、检索 1.5s、修复轮次、token                          |
| T2 慢/大量占位图           | 本地库命中、搜索配额、图片模型、素材解析策略                           |
| 任务 FAILED                | `generation_jobs.error_code` + `stage_timings` + 对应 runbook          |
| PDF 裁切                   | render PDF 缩放计算，不要强制 scale 1.0                                |
| 中文豆腐块                 | 字体 coverage、容器系统 Noto、render failure 指标                      |
| 导出下载 404               | export 的当前 DB 归属与 `storage_key`，不要只看路径                    |
| 告警一直“正常”             | `test:alerts`、指标是否在 catalog 且实际注册                           |
| 模型池配置不生效           | tier 区间、enabled、60秒缓存、图像候选是否被时延预算截断               |
| 生成按钮显示 CR 但提交 402 | 必须信服务端 quote 的 `sufficient`；检查价格版本缓存、并发 hold 与余额 |
| 钱包余额/冻结不一致        | 查 `credit_holds` 状态和只追加 ledger；不要手工直接改 wallet           |
| `TravelCreditUnpriced`     | 新模型或 SKU 缺精确价与 `:*` 兜底；补价目并发布新版本                  |
