# 旅行计划信息图系统 V1 — 用户需求清单

> **版本**：v1.1（2026-08-18）
> **修订记录**：
> - v1.0：初版，按详细设计 V1.6 提炼。
> - v1.1：FR-3.4 增加图片素材三级获取链（本地图库 → 联网搜索 → AI 生图，均回存本地图库）；新增 FR-6.6 生成内容的空间化存储与索引。

---

## 一、核心功能需求（FR）

### FR-1 旅行需求提交

- **FR-1.1** 用户可通过表单提交旅行诉求：出发地/目的地、起止日期、出行人（成人/儿童/老人）、预算（币种/口径/上下限/包含项）、节奏（宽松/均衡/紧凑 + 每日景点数/步行上限/最早出发时间）、结构化条件（24 项条件字典：兴趣/交通/住宿/无障碍/饮食/作息，分 MUST/SHOULD）、自由文本补充（≤500 字）。
- **FR-1.2** 提交后**全程无需人工介入**，全链路自动完成（验收标准 1）。
- **FR-1.3** 输入非法时同步返回明确的字段级错误（12 条冲突检查 N-01～N-12，如日期过期、天数超 1～14、预算不可行、出发地=目的地等），不进入生成流程。
- **FR-1.4** V1 范围限定：单目的地、1～14 天、中文（zh-CN）、CNY、日期无弹性；多目的地/目的地推荐/日期弹性明确拒绝并返回对应错误码。

### FR-2 AI 自动生成旅行计划

- **FR-2.1** 由大模型生成结构化旅行计划（TravelPlan）：标题、总预算、逐日行程（时间段/地点/坐标/时长/费用/步行距离/儿童友好标注）、美食推荐、路线推荐、必做事项、拍照机位、交通贴士、门票预约提醒、订座建议、每日预算明细。
- **FR-2.2** 计划必须经过 Schema 校验 + 约 30 条业务规则校验（日期一致性、时间不重叠、预算自洽含住宿、节奏区间、MUST 条件满足等），并**自动修复**（程序化修复最多 3 轮 + LLM 定向重生成最多 2 次）。
- **FR-2.3** 用户勾选的 MUST 条件不可被静默丢弃，无法满足时明确失败（`PLAN_HARD_CONSTRAINT_UNSATISFIABLE`），提示用户放宽条件。
- **FR-2.4** **绝不向用户展示未通过校验的模型草稿**（验收标准 15）；修复失败的版本仅落库排查、API 返回 404。
- **FR-2.5** 生成时全局检索历史计划作为参考（跨用户、脱敏投影），提高计划质量；无参考时正常生成。

### FR-3 页面与信息图产出

- **FR-3.1** 每份计划产出 **N+1 个页面**：每日一张信息图（DAILY_POSTER）+ 一个响应式完整计划页（FULL_PLAN）（验收标准 4）。
- **FR-3.2** 页面由 React 模板（`travel_infographic_v1` / `travel_full_plan_v1`）渲染 HTML，中文字体自托管、无豆腐块。
- **FR-3.3** 页面**不得有文字遮挡与明显溢出**（验收标准 9）；溢出时按"压缩文案 → 隐藏低优先级模块 → 宽松版式 → 标记 DEGRADED"逐级适配，**不靠丢行程内容适配画幅**。
- **FR-3.4** 素材自动配齐：Hero 图、景点图、美食图、本地 SVG 图标、程序生成路线图 SVG。其中**图片类素材**按以下三级优先链获取：
  - **FR-3.4.1 本地图库优先**：先在本地素材图库中按标签检索匹配的图片，命中即直接复用；
  - **FR-3.4.2 联网搜索兜底一**：本地未命中时，联网搜索获取图片；搜索命中后**自动打标签**（如目的地/POI、素材角色〔景点/美食/Hero〕、主题风格、entity_type 等），并**保存入本地图库**，供后续请求复用；
  - **FR-3.4.3 AI 生图兜底二**：联网也搜索不到时，调用大模型生成图片；**生成的图片同样打标签并保存入本地图库**；
  - **FR-3.4.4 图库按标签分类管理**：本地图库以标签体系组织与索引（分类、检索、去重均基于标签），图库随使用持续积累，命中率逐步提升；
  - **FR-3.4.5 来源与版权记录**：无论来自联网搜索还是 AI 生成，入库时必须记录来源（source_type）、版权/授权信息（license）与生成元数据，与 SEC-5「所有素材可追踪来源」保持一致。
  - ⚠️ 合规注意：「联网搜索」应限定为**有授权 API 的图片源**（如已签约图库/CC 协议源），入库时校验 `license_type` 非空，避免版权不明的图片进入本地图库被长期复用（对应详细设计第二十章「外部图片」约束）。
- **FR-3.5** 素材全链路降级不阻断：路线图失败 → 文字路线；Hero 失败 → 渐变背景；景点/美食图缺失 → 占位图；图标加载成功率须 100%（验收标准 5～8）。

### FR-4 导出与下载

- **FR-4.1** 支持导出 **PNG 长图**与**可打印 PDF**；HTML/PNG/PDF 至少两种输出可用（验收标准 10）。
- **FR-4.2** 导出范围可选：单日 / 全部天（PDF 合并为 1 个 N 页文件）/ 完整计划页。
- **FR-4.3** 导出产物存对象存储，返回 7 天有效的预签名下载 URL，过期可重新获取签名而不重渲染。
- **FR-4.4** 部分天导出失败时返回 `PARTIAL` + 成功项，不整体失败。
- **FR-4.5** 相同参数的导出请求幂等复用，不重复渲染（验收标准 13）。

### FR-5 任务与进度

- **FR-5.1** 生成为异步任务：提交后立即返回 `job_id`，用户可轮询任务状态与进度（0～100 单调递增 + 用户可读的中文阶段文案）。
- **FR-5.2** **渐进式交付**：T1 先看到文字版计划 → T2 看到含图 HTML 页 → T3 后台完成 PNG/PDF 并通知，不阻塞前两段。
- **FR-5.3** 支持取消进行中的任务（`POST /generation-jobs/{id}/cancel`）。
- **FR-5.4** 同一 `client_request_id` 并发/重复提交幂等去重，只产生 1 个计划；幂等命中不扣配额。
- **FR-5.5** 失败必须有明确错误码（AUTH/REQ/PLAN/ASSET/RENDER/EXPORT/JOB/SYS 八域）+ `retryable` 标记 + 重试入口（验收标准 14）。

### FR-6 用户体系（匿名 + 注册双模式）

- **FR-6.1** **未注册用户可直接生成**：首次访问自动建匿名账号（Cookie 令牌），生成端点永不因缺身份返回 401。
- **FR-6.2** 匿名用户能力：提交生成、查看自己的计划、导出 PNG/PDF、历史列表（后端就位，前端界面可延后）；不可跨设备、数据保留 30 天。
- **FR-6.3** 注册（邮箱+密码）后：`user_id` 不变、**历史计划自动继承**（零迁移升级）；数据长期保留、可跨设备。
- **FR-6.4** 先匿名后登录已有账号时执行匿名归并（幂等、可重试、保留审计链）。
- **FR-6.5** 账号级敏感操作（改邮箱/改口令/删账号）仅对注册用户开放。
- **FR-6.6** 生成内容的空间化存储与索引：
  - **FR-6.6.1 按用户空间归档**：每次生成的全部产物（TravelPlan、ViewModel、HTML/PNG/PDF、关联素材绑定）保存到发起用户的空间内，以 **`user_id` + 本次生成时间**作为归档维度，同一用户的内容按时间组织、可按时间范围浏览与检索。
  - **FR-6.6.2 全局唯一内容 ID**：每次生成自动分配一个**全局唯一、时间有序的内容 ID**（建议 UUIDv7 / ULID，ID 本身编码生成时刻），作为该次生成所有产物的主索引；后续内部查找、日志关联、客服排查均以此 ID 为锚点。
  - **FR-6.6.3 匿名用户通用空间**：匿名用户的生成内容统一保存到一个**通用（公共）命名空间**下，不建独立的每人目录，仅以 FR-6.6.2 的唯一 ID 索引，并在索引记录中保留其匿名 `user_id` 归属字段。
    - ⚠️ 约束：通用空间只是**存储组织方式**，不是可见性边界 —— 对外访问仍按 SEC-1 强制 `user_id` 隔离，匿名 A 不可见匿名 B 的内容。
  - **FR-6.6.4 存储路径约定**（对象存储 / 逻辑目录）：
    - 注册用户：`users/{user_id}/{yyyyMM}/{content_id}/...`
    - 匿名用户：`anon/{yyyyMM}/{content_id}/...`
    - 路径含年月分段，便于按时间批量管理与生命周期清理。
  - **FR-6.6.5 内部查找能力**：支持按「唯一内容 ID」「`user_id`」「生成时间范围」及其组合进行内部检索（运维、客服、问题排查场景），无需遍历用户目录。
  - **FR-6.6.6 身份升级/归并时的内容归属**：匿名升级为注册（`user_id` 不变）时，通用空间内容**只改归属标记、不搬运文件**；匿名归并到已有账号（`user_id` 变化）时，仅更新索引记录的归属 `user_id`，对象存储路径保持不变（唯一 ID 保证仍可定位）。
  - **FR-6.6.7 保留策略对齐**：通用空间内容随匿名数据 30 天保留期一并清理（SEC-6）；升级/归并后转为注册归属的内容不受匿名清理影响，转为长期保留。
  - 衔接说明：① 与详细设计 3.6.2「统一 users 表」不冲突 —— 匿名用户本身就有真实 `user_id`，数据库层归属列保持原设计不变，「通用空间」体现在对象存储物理路径组织与索引表设计上；② 内容 ID 建议直接复用 `plan_version_id`（生成策略改为 UUIDv7/ULID 即天然满足时间有序），避免引入平行 ID 体系。

### FR-7 历史计划

- **FR-7.1** 生成结果按 `user_id` 索引长期存储，支持多版本（V1 无重新生成入口，多版本机制为 V2 预留）。
- **FR-7.2** 提供历史计划列表端点（分页、游标），V1 前端仅入口占位。

## 二、安全与隐私需求（SEC）

- **SEC-1** 用户只能访问自己的计划/任务/导出（验收标准 11）；他人资源统一 404（防 ID 枚举），SQL 层强制 `user_id` 过滤，匿名与注册隔离强度相同。
- **SEC-2** 跨用户历史检索只读**脱敏投影**：不含日期、金额、人员构成、自由文本、约束报告与任何标识符；由数据库列级权限保证（检索角色无 `plan_json` 权限）。
- **SEC-3** 匿名令牌为 CSPRNG 随机值、服务端存哈希、HttpOnly/Secure Cookie；口令用 Argon2id 哈希。
- **SEC-4** 防刷：匿名创建按 IP 限速、单 IP 每日生成总量兜底、登录失败限速。
- **SEC-5** 所有素材可追踪来源与版权（source/license/AI 生成元数据，验收标准 12）；模型输出剥离 URL/HTML；错误消息不泄漏内部细节。
- **SEC-6** 匿名数据 30 天到期清理，清理前脱敏知识转存 `plan_knowledge`（无标识符）。

## 三、性能与成本需求（NFR）

- **NFR-1** 分段 SLA：**T1 计划可读 P95 < 75 秒**；**T2 页面可看 P95 < 110 秒**；T3 产物就绪 P95 < 240 秒（≤7 天）/ < 420 秒（8～14 天）；计时起点为入队时刻（含排队）。
- **NFR-2** Hero 图缓存优先（命中率 ≥ 80%），AI 实时生成超时 20 秒即降级，单计划最多 2 次实时 AI Hero。
- **NFR-3** 单任务成本上限：LLM 1 主调用 + 最多 2 次重生成；AI 图片 ≤ 3 张（连续失败 2 次即停用 AI）；超出即降级不继续付费。
- **NFR-4** 用户配额（全部可配置）：匿名/注册分档 —— 每分钟 1/3 次、每日 5/5 个、每月 10/20 个、同时 1 个进行中任务、导出 3/10 次、实时 AI Hero 0/2 次。
- **NFR-5** 全局熔断：AI 图片日调用达预算阈值时全局降级为"素材库+占位图"模式，服务不中断。
- **NFR-6** 可观测性：Prometheus 全链路指标（任务时长/里程碑/LLM token/校验违规/缓存命中/降级/导出等约 20 项）+ OpenTelemetry Trace + 结构化日志 + SLA/缓存/字体/降级告警。

## 四、平台与技术约束（CON）

- **CON-1** 全 TypeScript monorepo（Node 24 LTS + Next.js/React），非 Python/FastAPI。
- **CON-2** 运行目标 **Linux 容器**（x86-64/glibc、非 root、`/dev/shm`、大小写敏感），开发可在 Windows/macOS，CI 必须 Linux 验证（L-01～L-10）+ 优雅停机（SIGTERM 不留悬挂任务）。
- **CON-3** 存储：PostgreSQL + pgvector（计划/用户/向量检索）、Redis（BullMQ 队列、幂等锁、配额计数）、S3 兼容对象存储（产物文件）。
- **CON-4** 大模型边界：只输出结构化 JSON，**不生成 HTML/CSS/图片 URL、不写数据库、不生成 React 代码**；ID 由程序注入。
- **CON-5** 明确不支持（V1）：航班酒店实时库存、自动下单、点评聚合、多人协同、自由版式、多目的地、目的地推荐、日期弹性。

## 五、验收口径（摘要）

15 条 V1 验收标准 + 19 条可度量门禁（详细设计 24.1），核心通过线：

- 20 个端到端用例全绿（覆盖 1/3/7/14 天与多种约束组合）；
- 图标加载失败恒为 0；
- 越权访问全部返回 404，无信息泄漏；
- 同一 `client_request_id` 10 并发只产生 1 个计划；
- 故障注入（SVG 渲染器抛错 / AI 图片全超时 / 素材库置空）下任务仍 COMPLETED；
- 检索投影逐字段脱敏断言 100% 通过；
- Linux CI 全绿（L-01～L-10）、视觉基线由容器内产出。

门禁机器可读形态在 `tools/acceptance-gates.mjs`（`pnpm gate`）。
