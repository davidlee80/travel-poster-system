## 一、这个服务做什么

你填写出发地、目的地、日期、预算与偏好，我们用大语言模型为你生成一份逐日的
旅行计划，并渲染成可保存、可打印的信息图。

**生成的计划是参考建议，不是预订，也不构成任何承诺。** 营业时间、票价、交通
时刻都可能与实际不符 —— 出行前请自行核对。我们不承担因依据本服务的建议
而产生的任何损失。

---

## 二、需要注册才能使用

这是本政策**最需要你注意的一节**。

**生成计划需要先注册一个账号**（邮箱 + 口令）。未注册的访客可以打开页面、
填写表单，但提交生成会被拒绝。

| 已注册用户         |                      |
| ------------------ | -------------------- |
| 计划保存多久       | 长期，直到你删除账号 |
| 跨设备访问         | 能                   |
| 每日生成额度       | 5 个计划             |
| 每月生成额度       | 20 个计划            |
| 每个计划的导出次数 | 10 次                |

**我们如何认得你**：登录后在你的浏览器里放一个随机的会话令牌（Cookie
`tp_session`，`HttpOnly`）。它不含你的任何身份信息，只是一个随机串，
用来对应到你的账号。清掉浏览器数据只需要重新登录，**不会丢数据** ——
你的计划挂在账号下，不挂在浏览器上。

### 2.1 关于「未登录也能生成」

本服务曾支持不注册直接生成，这个入口现在**默认关闭**。它是一个可以重新打开的
配置项，因此本节说明它开启时的数据行为，以及关闭之前产生的数据怎么处理。

未登录使用时，我们在浏览器里放一个随机令牌（Cookie `tp_anon`）来认得你 ——
它同样不含任何身份信息。这种方式有一个**无法回避的限制**：清掉浏览器数据、
换浏览器或换设备之后，之前生成的计划就再也无法访问了。我们没有任何其他方式
能把那些计划与你对应起来。

**这样产生的计划保存 30 天**，之后被删除。这不需要你做任何事，也不可撤销。
入口关闭之前留下的数据仍然按这个规则清理，不会因为入口关闭而提前删除或
无限保留。

如果你手上还有这样一个访客身份，注册**不会丢掉已经生成的计划** ——
它们会自动归到你的账号下（原来的匿名身份就是你的账号，只是补上了邮箱与口令）。

## 三、我们收集什么

### 3.1 你主动提供的

- **旅行需求**：出发地、目的地、日期、人数与年龄段、预算区间、偏好与忌口、
  自由文本备注。
- **账号信息**：邮箱、口令。口令以 Argon2id 哈希存储，我们**无法**读出它的原文。
  你可以在登录状态下修改口令（需要输入当前口令；修改后其他设备上的登录会
  全部退出）。**但目前没有「忘记口令」的自助找回** —— 本版本不具备发送邮件的
  能力，因此口令一旦遗忘，我们也无法帮你恢复账号。请妥善保存它。

### 3.2 技术上必然产生的

- **IP 地址**：仅用于防滥用限速，且**只写入独立的安全审计日志**
  （保留 90 天），不进业务日志、不与你的计划内容关联。
- **生成过程的技术记录**：每个阶段的耗时、使用的模型、消耗的 token 数、
  失败时的错误码。用于排查与成本核算。

### 3.3 我们不收集的

- 精确位置（我们只用你填写的城市名与目的地 ID）
- 通讯录、相册、设备标识符
- 任何第三方广告或分析追踪脚本

## 四、关于「脱敏行程知识」

这一节说明一件与直觉相反、但对你的隐私很重要的事。

**为了让后来的用户拿到更好的计划**，我们会从每份生成的计划里提取一份
**脱敏的结构摘要**，例如「杭州 · 5 天 · 偏文化 · 每日 3～4 个景点 ·
西湖与运河常被安排在相邻两天」。

这份摘要**不含**：

- 你的任何标识符（不含用户 ID、计划 ID、请求 ID）
- 出行日期（只保留季节与天数）
- 预算金额（只保留档位）
- 人员构成（不含人数与年龄）
- 你写的自由文本原文
- 任何可以指回你的东西

**它的保留期与你的计划不同**：你的计划（含上面全部个人参数）在 30 天后被删除
或随你的账号删除而删除；而这份摘要在删除**之前**被转存到一个不含任何标识符的
知识库里，**长期保留**。

**为什么这样设计**：一份「杭州的 5 天行程通常这样安排」的知识与「谁在什么时候
去了杭州」是两件事。前者对所有用户有价值且不指向任何人，后者是你的个人数据。
把两者分开，我们才能既按承诺删除你的数据、又不让每个新用户都从零开始。

**如果你不接受这一点**：请不要使用本服务。我们无法为单个用户排除这一步 ——
在数据已经不可识别之后，我们也无法再找出「哪一条摘要来自你」。

## 五、我们如何使用第三方

| 用途               | 数据流向         | 传出的内容                                            |
| ------------------ | ---------------- | ----------------------------------------------------- |
| 生成计划           | 大语言模型服务商 | 你的旅行需求（**含自由文本**）；不含邮箱、IP、任何 ID |
| 生成配图           | 图片生成服务商   | 目的地名与风格描述；**不含**你的任何需求参数          |
| 存储图片与导出文件 | 对象存储         | 生成的图片与 PDF/PNG 文件                             |

模型服务商是否用请求数据训练模型，取决于我们与它签订的条款；
我们选择供应商时会优先要求**不用于训练**，但这一点由供应商的条款约束，
不由本政策保证。**因此：不要在自由文本里写任何你不愿意交给第三方的内容**
（证件号、联系方式、健康细节等）。

## 六、你的权利

「未登录」一列说明的是第 2.1 节那种存量访客数据。

| 权利           | 已注册             | 存量访客数据（见 2.1）                  |
| -------------- | ------------------ | --------------------------------------- |
| 查看自己的计划 | 能                 | 能（仅当前浏览器）                      |
| 导出带走       | 能（PNG / PDF）    | 能（PNG / PDF）                         |
| 删除单个计划   | 能                 | 能                                      |
| 删除全部数据   | 删除账号，立即删除 | 清浏览器数据即失去访问，30 天后自动删除 |
| 改口令         | 能（需当前口令）   | 不适用（没有账号）                      |
| 改邮箱         | 暂不支持           | 不适用（没有账号）                      |

**删除账号会删除什么**：你的邮箱、口令哈希、全部计划与导出产物。
**不会删除**第四节所说的脱敏摘要 —— 它此时已不含任何指向你的信息。

## 七、安全

- 传输全程 HTTPS。
- 口令用 Argon2id 哈希，不可逆。
- 会话令牌是随机不透明串，`HttpOnly` + `Secure` + `SameSite=Lax`。
- 我们的日志在写入时就剥离邮箱、口令、会话令牌、你的自由文本原文与完整需求
  载荷 —— 这不是靠人记得，而是由序列化层强制（含一道静态检查确保没人绕过它）。
- 生成的图片可公开访问（URL 不可猜测但不需要凭据）；**导出文件需要签名 URL，
  7 天后失效**。

---

## 八、儿童

本服务不面向 14 岁以下儿童。行程里可以包含儿童的年龄段（用于安排适合的活动
与作息），但我们不收集儿童的姓名或任何其他信息。

---

## 九、变更

本政策变更时会在界面上提示。**涉及保留期或第三方数据流向的变更**，我们会在
生效前提示，而不是静默更新。

---

## 十、待确认事项（上线前必须解决）

> 这一节在正式发布时删除。

1. **运营主体、联系邮箱与适用法律** —— 需要产品/法务提供。
2. **模型与图片服务商的具体名称**，以及它们的「不用于训练」条款是否落纸。
   第五节现在写的是「取决于条款」，正式文本里应当明确。
3. **数据存放地域**。跨境传输（如果模型服务商在境外）需要单独一节说明。
4. **儿童年龄下限**（现写 14 岁）与当地法规是否一致。
5. **删除请求的响应时限**。现在的实现是即时删除，正式文本里应当给一个承诺值。
6. **忘记口令怎么办**。第 3.1 节现在如实写着「没有自助找回」，而这对一个只有
   邮箱与口令两个凭据的账号来说是个硬伤：忘了就是永久失去账号里的全部计划。
   要解决它需要发送邮件的能力（本版本没有）。上线前必须二选一：接入邮件并做
   重置流程，或者提供一条人工申诉通道并在这里写明它。
