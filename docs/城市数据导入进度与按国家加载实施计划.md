**城市数据导入与跨洲关联实施说明**

Python 导入脚本已实现“国家数据唯一保存，大洲索引引用”。前端仍读取旧城市数据，按需加载部分保留为后续接入工作。

**1. 输入与名称补全**

国家、城市信息来自 Markdown，不预置名称映射，也不默认读取旧的 apps/web/src/data/cities.json。新增国家代码、城市英文名依次使用 Markdown 明确信息、联网查询、拼音兜底；重复导入保留已生成数据的 code 和城市 ID。

输入方式不变：传入大洲目录、多个目录或单个 Markdown。仅扫描指定目录当前层的 .md／.MD 文件，按绝对路径去重。

~~~powershell
python tools/extract-cities-from-md.py "E:\Doc\Prompt\亚洲" --dry-run
python tools/extract-cities-from-md.py "E:\Doc\Prompt\亚洲" "E:\Doc\Prompt\欧洲"
~~~

每个 Markdown 对应一个国家，允许景点分布在多个大洲。按各行内容确定关联，不由输入目录名强制限定国家归属。混合多个国家的文件报错。

原九列继续支持：景点 ID、景点中文名、景点英文名、大洲、国家、城市、区域、经度、纬度。有表头时按列名解析，可增设“国家代码”“城市英文名”，或使用“国家（CN）”“城市（English）”。景点英文名不作为城市英文名。

**2. 输出结构**

~~~text
apps/web/public/data/
  index.json
  countries/
    示例国.json
    其他国家.json
  Asia/
    index.json
  Europe/
    index.json
~~~

国家完整城市数据只保存在 countries/<国家名>.json。大洲目录只保存导航索引，多个大洲引用同一国家文件。所有索引的 data_file 都相对于 data 根目录，而非当前大洲目录。

大洲目录固定使用 Asia、Europe、Africa、NorthAmerica、SouthAmerica、Oceania、Antarctica。国家名来自 Markdown，别名经相同 code 合并到已有文件。

~~~json
{
  "code": "XX",
  "name": "示例国",
  "continents": ["Asia", "Europe"],
  "cities": [
    {"id": "xx-alpha", "name": "城市甲", "continents": ["Asia"], "lat": 30, "lng": 100},
    {"id": "xx-beta", "name": "城市乙", "continents": ["Asia", "Europe"], "lat": 40, "lng": 30}
  ]
}
~~~

continents 表示 Markdown 景点记录涉及的大洲，不代表国家政治归属，也不从单个景点推断整个国家唯一的大洲。

**3. 合并与统计**

- 国家按 code 唯一保存，同名既有国家复用 code。Markdown 明确代码与已有 code 冲突时报告错误。
- 同一国家同名城市合并，保留原 ID 和首次有效坐标；大洲取去重后的并集。
- 同一城市跨洲仍是一个城市对象。新增大洲关联不增加国家或城市计数。
- 城市英文 slug 碰撞继续使用后缀处理；跨洲不重新分配 ID。
- 国家 continents 汇总城市关联，数组使用排序后的英文大洲名称。
- 增量导入保留本次输入未出现的国家、城市及已有大洲关联，不执行删除同步。
- 当前仍以同国同名作为城市去重依据；同国内不同地点恰好同名的精细辨识属于后续模型扩展。

**4. 索引与前端接入约定**

总索引使用 schema_version: 3：

| 字段 | 内容 |
| --- | --- |
| countries | 每国一条：code、name、continents、city_count、data_file、revision |
| continents | 每洲一条：name、country_count、city_count、data_file、revision |
| updated_at | 实际数据变化时更新；重复导入保持不变 |
| revision | 对应文件内容的 SHA-256 摘要 |

大洲索引包含 schema_version、continent 和 countries，每个国家条目为：

~~~json
{
  "code": "XX",
  "name": "示例国",
  "data_file": "countries/示例国.json",
  "revision": "<国家文件摘要>",
  "city_count": 1,
  "total_city_count": 2
}
~~~

大洲索引 city_count 是该国涉及当前大洲的城市数；total_city_count 是全国去重城市数。总索引 countries 的 city_count 也是全国数量。跨洲城市在各相关大洲的筛选数量中各出现一次，全球数量必须从国家列表计算，不能相加各洲数量。

前端后续接入：初次请求索引，选国家后只请求一次国家完整文件；如需按洲筛选，使用城市 continents 数组。不同大洲入口按文件路径与 revision 共享缓存，保留异步状态、重试、忽略过期响应、历史值回显和自定义地点行为。

切换前端数据源前单独检查旧行程 ID 兼容性，不能假设从 Markdown 重新生成的 ID 与旧 cities.json 完全相同。

**5. 进度、目录与写入恢复**

先显示 Markdown 总数及 0/N；文件解析、联网补全和内存合并结束后推进进度，末尾显示已处理数／总数。失败和空文件也计入已处理，分别统计结果。N/N 后另行显示校验与保存状态，写入完成才报告完成。

交互终端单行刷新，日志清行后输出再重画；非交互终端使用普通进度行。

正式写入自动创建 data、countries 及涉及的大洲目录。先验证名称和输出路径，拒绝非法文件名和路径跳转。--dry-run 不创建目录、文件、备份，也不执行迁移。

所有变化文件先暂存校验，备份旧总索引、国家文件及全部大洲索引；逐文件原子替换，总索引最后提交。正常异常回滚所有变化；进程中断后，下次正式运行按恢复记录还原。备份位于非公开目录 tmp/city-data-backups/。

多个固定文件路径不能实现整个目录的原子更新。因此在工作区或构建阶段导入，生产部署完整验证版本。固定名称资源使用 HTTP 重新验证，不配置长期 immutable 缓存。

**6. 旧目录迁移**

兼容 schema_version: 2 的中文／英文大洲目录：

1. 校验旧索引、国家文件和摘要。
2. 将旧单一 continent 转成国家及城市的 continents 数组。旧数据只有一个大洲时按已保存信息迁移，后续 Markdown 可补充关联。
3. 移至 countries/<国家名>.json，保留名称、城市 ID、坐标和全部城市。
4. 生成 schema 3 总索引及各洲索引。
5. 在同一备份／回滚事务中删除旧路径国家文件，提交后仅清理空目录。

下一次成功导入时，索引内的旧版国家文件一起迁移。旧单体 cities.json 不自动作为输入。

**7. 验收范围**

- 文件筛选、终端进度、联网／拼音兜底、Markdown 信息优先、重复导入及 dry-run。
- 单文件含多个大洲；同国跨文件、跨输入目录合并。
- 跨洲城市 ID 不变、坐标保留、关联取并集，新增统计不重复。
- 国家只有一个正式文件，各洲引用相同路径；洲内和全国数量分别准确。
- 单洲数据继续正常工作，重复导入输出不变。
- schema 2 迁移保持原 ID 和坐标，撤回旧文件，索引保持一致。
- 国家文件、大洲索引和总索引写入失败时整体回滚，中断可恢复。
- 已有索引损坏或关联数量错误时拒绝继续写入。
