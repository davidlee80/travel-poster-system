# 代码审核 TODO 台账

本目录用于记录代码审核、设计对照和上线检查中发现的问题。问题修复后不删除，改为
“已关闭”并填写解决日期、提交或代码证据，以便追溯产品边界为什么发生变化。

## 维护规则

- 问题编号格式：`AUD-YYYYMMDD-NNN`，日期为首次确认日期。
- 每次审核新增一份 `YYYY-MM-DD-代码审核问题清单.md`；同一问题不要重复建号。
- 状态统一使用：`待修复`、`处理中`、`待产品决策`、`待外部接入`、`待验证`、`已关闭`。
- 优先级统一使用：`P0`（阻断/合规）、`P1`（核心闭环）、`P2`（体验/运营）、`P3`（优化）。
- 已关闭问题必须保留原始影响、证据、解决方式、解决日期和验证结果。
- 如果代码与设计文档口径不一致，记录“当前产品决定”，不要只改其中一处。
