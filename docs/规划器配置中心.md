# 规划器配置中心

规划器的可选项保存在 PostgreSQL，而不是散落在 React 组件中。浏览器读取
`GET /api/v1/planner/config` 的当前发布版本；读取失败时才使用代码内置值兜底。

## 数据表

- `planner_config_versions`：版本状态（`DRAFT`、`PUBLISHED`、`ARCHIVED`）。数据库约束保证同时只有一个发布版本。
- `planner_config_options`：选项明细。`field_key` 是控件分类，`option_key` 是提交给后端的稳定值，`label` 是展示文字，`metadata` 存图标、预算区间等附加配置。
- `planner_config_current`：当前发布版本的只读视图。

删除选项时不要物理删除，将 `enabled` 改为 `FALSE`。这样历史版本可追溯，回滚时也不会丢配置。

## 修改与发布

下面以当前版本 1 克隆出版本 2 为例。所有修改都先发生在草稿，不会影响线上用户。

```sql
SELECT clone_planner_config(1, 2, '调整兴趣标签');

UPDATE planner_config_options o
SET label = '博物馆与艺术展'
FROM planner_config_versions v
WHERE o.version_id = v.id
  AND v.version = 2
  AND o.field_key = 'interest.tags'
  AND o.option_key = 'interest.art_museum';

UPDATE planner_config_options o
SET enabled = FALSE
FROM planner_config_versions v
WHERE o.version_id = v.id
  AND v.version = 2
  AND o.field_key = 'interest.tags'
  AND o.option_key = 'interest.nightlife';

SELECT publish_planner_config(2);
```

发布是单事务操作：原发布版自动归档，目标草稿变为发布版。API 最多缓存 60 秒，无需重启服务。

## 当前分类键

| `field_key`                          | 页面控件         |
| ------------------------------------ | ---------------- |
| `booking.existing`                   | 已有订单         |
| `traveler.senior_mobility`           | 长者行动能力     |
| `traveler.tags`                      | 同行偏好标签     |
| `budget.tiers`                       | 预算档位         |
| `budget.included_items`              | 预算包含项       |
| `budget.focus_tags`                  | 预算侧重标签     |
| `pace.intensity`                     | 行程强度         |
| `pace.attractions_per_day`           | 每日景点数       |
| `pace.walking_limit_km`              | 步行上限         |
| `pace.route_shape`                   | 路线结构         |
| `pace.need_tags`                     | 无障碍与作息标签 |
| `transport.mode_tags`                | 交通标签         |
| `transport.lodging_type_tags`        | 住宿类型标签     |
| `transport.lodging_requirement_tags` | 住宿要求标签     |
| `diet.tags`                          | 饮食标签         |
| `interest.tags`                      | 兴趣标签         |

标签类 `option_key` 是后端条件契约的机器码，展示文案、顺序、启停均可直接改配置。
新增全新标签时使用 `<域>.<英文小写名称>`，域必须是 `interest`、`transport`、
`accommodation`、`budget`、`accessibility`、`diet`、`schedule` 之一。API 会按当前
发布版本校验机器码，未发布或拼错的码不会进入生成任务。
