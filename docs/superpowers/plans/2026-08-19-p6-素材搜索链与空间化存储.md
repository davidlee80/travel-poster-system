# P6 素材搜索链与空间化存储 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: 用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 逐任务实施。步骤用 `- [ ]` 复选框跟踪。

**Goal:** 让搜索到的授权图片自动入库并在第二次请求被库内命中，同时让导出产物按 15.4 的用户空间路径归档、匿名清理以数据库归属为准且不误伤已归并数据。

**Architecture:** 两组互不依赖的改动。A 组在既有降级链的 `fallback_level` 1 空位插入「授权图源搜索 → 自动入库」一层，复用 11.2 的 `processImage` 与 `ingestAsset`，新增内容指纹去重；B 组把 `travel_plan_versions.id` 换成 UUIDv7 使其成为 `content_id`，据此派生导出对象键，并让 retention-worker 在删行之前按数据库中记录的真实键删除对象。

**Tech Stack:** Node 24 LTS、pnpm workspaces + Turborepo、TypeScript strict、Zod、vitest、PostgreSQL 17 + pgvector、Redis、S3 兼容对象存储（MinIO）、Prometheus。

**Spec:** [旅行计划信息图系统 V1 详细设计.md](../../旅行计划信息图系统%20V1%20详细设计.md) 的 9.3～9.6、13.11、15.1、15.4、21.4、24.1（R-45～R-52）；任务编号与验收口径见 [旅行计划信息图系统 V1 实施计划.md](../../旅行计划信息图系统%20V1%20实施计划.md) 的「P6 素材搜索链与空间化存储」。

## Global Constraints

以下是全仓库既有约束，每个任务的要求都隐含包含本节，逐条数值照抄设计稿：

- **TypeScript strict** 且开启 `noUncheckedIndexedAccess`、`exactOptionalPropertyTypes`、`verbatimModuleSyntax`。索引访问必须显式判空，可选属性不可传 `undefined`，类型导入必须带 `type`。
- **Linux 是唯一正确性基准**（22.3）。本机（Windows）跑通不算通过。
- **跨平台护栏**：路径字面量禁止含 `\`（ESLint 规则）；新文件换行 LF。
- **指标**：禁用 `user_id` / `email` / `slot_id` / `entity_name` 等高基数标签（`packages/observability/src/labels.ts` 的 `ValidLabel<T>` 编译期拦截）；**任何新注册的 `travel_*` 指标必须同时登记进 `packages/observability/src/catalog.ts`**，否则 `pnpm test:alerts` 的双向断言失败。
- **迁移**：前向单向、每迁移一事务、可重复执行幂等；文件名 `NNNN_<slug>.sql` 放 `infrastructure/migrations/`。
- **不新增错误码**：13.7 已有 `ASSET_LICENSED_SOURCE_UNAVAILABLE`（`blocking: false`），搜索层的全部失败都用它。
- **搜索层约束值**（9.6，不可上调）：单次搜索超时 **5 秒**；单任务搜索上限 **≤ 8 次**；单任务连续失败 **2 次**即停用搜索层；匿名与注册**同额**；失败/超时/熔断一律非阻断，记入 `generation_jobs.warnings` 后任务继续。
- **入库门禁**（9.6）：MIME 白名单 + 最小分辨率、`license_type` 非空、`content_hash` 去重、`quality_score` **< 0.3 不入库**。打标只取 `AssetRequirement` 上下文，**不做图像理解**。
- **`source_metadata` 对 `LICENSED_SOURCE` 必填**：provider、original_url、检索词、license 原文与到期日。
- **对象清理硬约束**（R-50）：一切清理以数据库归属为准，**禁止按路径前缀清理** —— `anon/` 前缀下混有已升级/已归并用户的长期数据。
- **`IMAGE_SEARCH_MODE` 默认 `fake`**。本轮只交付 fake 与适配器接口，`direct` 无适配器时**启动即失败**而不是运行时才发现。

## Task 7: UUIDv7 内容 ID（TP-6-10）

**Files:**

- Create: `packages/shared/src/uuidv7.ts` + `.test.ts`
- Modify: `packages/shared/src/index.ts`、`apps/generation-worker/src/generate-plan.ts:595`

**Interfaces:**

- Produces:

```ts
/** RFC 9562 UUIDv7：48 位毫秒时间戳 + 版本 7 + 74 位随机 */
export function uuidv7(nowMs?: number): string;
/** 从 v7 提取编码时刻；非 v7（含 v4 存量行）返回 null */
export function uuidv7Date(id: string): Date | null;
/** 范围扫描的边界 UUID：edge='min' 取该毫秒的最小值，'max' 取最大值 */
export function uuidv7Boundary(at: Date, edge: 'min' | 'max'): string;
```

实现要点：用 `randomBytes(16)` 后 `bytes.writeUIntBE(nowMs, 0, 6)` 写 48 位时间戳（`writeUIntBE` 上限恰好是 6 字节），再置版本位 `bytes[6] = (bytes.readUInt8(6) & 0x0f) | 0x70` 与变体位 `bytes[8] = (bytes.readUInt8(8) & 0x3f) | 0x80`。**不引入 `uuidv7` npm 包**：边界构造是这里的必需能力而那个包不提供，且 P1 已确立「减少一个依赖优于省二十行纯函数」（`oxipng` → `sharp` 的同一判断）。

边界值：`min` 尾部 `7000` + `8` + 15 个 `0`；`max` 尾部 `7fff` + `b` + 15 个 `f`（变体位只能是 `8|9|a|b`，因此不是 `f`）。

- [ ] **Step 1: 写失败的测试**

七条：生成的 ID 匹配 UUID 正则且版本位为 `7`、变体位在 `89ab`；同一毫秒内两次生成不相等；相邻毫秒生成的 ID 字典序递增（时间有序性，PostgreSQL 的 `uuid` 按字节比较，与 hex 字典序一致）；`uuidv7Date(uuidv7(t)) === t`；`uuidv7Date(randomUUID())` 为 `null`；`uuidv7Boundary(t,'min') <= uuidv7(t) <= uuidv7Boundary(t,'max')`（用 1000 次随机采样断言）；边界值本身是合法 UUID。

- [ ] **Step 2～4: 实现、通过、切换调用点**

`generate-plan.ts` 的 `const versionId = randomUUID()` 改 `uuidv7()`，并把该处注释补一句「它同时是 15.4 的 `content_id`」。若 `randomUUID` 在该文件再无其他用途则移除导入（只清自己造成的孤儿）。
