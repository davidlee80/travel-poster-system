# P7 关闭匿名入口 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: 用 superpowers:subagent-driven-development 或 superpowers:executing-plans 逐任务实施。步骤用 `- [ ]` 复选框跟踪。

**Goal:** 前端来的一切请求都必须是注册用户 —— 不再自动创建匿名号、不再接受 `tp_anon` 凭据，而匿名体系的建表、归并、保留期清理与 `anon/` 存储空间全部保留且仍有测试覆盖。

**Architecture:** 一个功能开关 `FEATURE_ANONYMOUS_ENABLED`（**默认 false**）拦在 `IdentityService.resolve()` 内部 —— 13.0 的四分支解析归它所有，因此这是唯一能同时覆盖「自动建号」与「已有 `tp_anon` 凭据」两条路径的位置。业务端点与 `resolveIdentity` 的签名不变。

**Tech Stack:** 与 P0～P6 相同。不新增依赖、不新增错误码、不新增迁移。

**Spec:** 本次是**产品决策驱动的方向反转**，不承接需求清单的既有条目。它反转的是详细设计 13.0 第 3.a 条「生成端点永不因缺身份返回 401」与 3.6 的双模式前提。需回写为 **R-54**。

## Global Constraints

沿用 P6 的全部约束（TS strict 三项、Linux 基准、路径护栏、指标须登记 catalog、迁移前向单向），另加本次特有的四条：

- **不新增错误码。** 13.7 已有 `AUTH_IDENTITY_REQUIRED`（401）与 `AUTH_ANONYMOUS_FORBIDDEN`（403），够用。
- **不动数据库。** 不加列、不删列、不加迁移 —— 这是「开关」而非「移除」的定义。
- **不删匿名代码路径。** `createAnonymous` / 归并事务 / retention 的匿名清理 / `anon/` 键构造全部保留，且各自的测试继续跑。它们是重新打开匿名时的安全网。
- **存量匿名数据照常走 30 天保留期清理。** 用户协议承诺的「未登录保存 30 天」因此**不需要修改**，retention-worker 一行不改。

## 三项已确认的口径

| 决定         | 结论                                                    |
| ------------ | ------------------------------------------------------- |
| 处置方式     | 功能开关拦在 API 层。可逆，随时能重新打开               |
| 存量数据     | 照常 30 天保留期清理 + 知识转存。不提前删、不改隐私政策 |
| 8 项匿名门禁 | 反转断言，门禁总数仍 **38** 项                          |

## 一处必须先解决的依赖

**验收用例的注册身份是靠匿名自举的。** `acceptance.integration.test.ts:276-290` 的做法是：
`GET /auth/session` 拿 `tp_anon` → 带着它 `POST /auth/register` → 得到 `tp_session`。
因此匿名入口一关，**21 个验收用例全部失败**，而不只是其中 10 个匿名用例。

`POST /auth/register` 本身支持无 `tp_anon` 的新建（TP-1-35 的第二场景），因此改法是让用例直接注册。这一项必须排在门禁反转之前 —— 否则 `pnpm gate` 的 #1～#4、#12、#19、#21 会一起红，看不出哪个是真问题。

## Task 2: `FEATURE_ANONYMOUS_ENABLED` 开关

**Files:** 改 `packages/shared/src/feature-flags.ts` + `feature-flags.test.ts`、`env.example`

**Interfaces:**

```ts
export interface FeatureFlags {
  readonly generationEnabled: boolean;
  readonly exportEnabled: boolean;
  readonly generationRolloutPercent: number;
  /**
   * 匿名身份入口。**默认 false**（P7）。
   *
   * 与其余两个开关的默认值相反，这是有意的：那两个是「正常开着，紧急时关」，
   * 而这一个是「产品已决定关闭，只有显式打开才恢复旧行为」。
   * 默认 true 会让任何忘记配置的部署静默重新开放匿名入口 ——
```

**不走 `decideFeature`**：那个函数按 `user_id` 分桶做百分比放量，而匿名判定发生在**身份存在之前**，没有 `user_id` 可用。混进去会迫使调用方编一个假 ID。

## Task 3: `IdentityService` 按开关短路（核心）

**Files:** 改 `apps/api/src/identity/service.ts` + `service.test.ts`

**Interfaces:**

```ts
export interface IdentityServiceDeps {
  // …既有字段…
  /** false 时：不自动建匿名号，且已有 tp_anon 凭据一律不解析（P7） */
  readonly anonymousEnabled: boolean;
}

export type ResolveResult =
  | { outcome: 'resolved'; identity: Identity; cookies: readonly CookieMutation[]; pendingMerge: … }
  /** 新增 cookies：拒绝匿名凭据时要顺便清掉它，否则浏览器每次都白带一次 */
  | { outcome: 'identity_required'; cookies: readonly CookieMutation[] }
  | { outcome: 'anon_creation_rate_limited'; retryAfterSeconds: number | null };
```

**为什么拦在 service 里而不是各路由**：`allowAnonymousCreation` 有 15 个调用点，路由层拦要改 15 处；而 `/auth/session` 根本不走 `resolveIdentity`（它直接调 `identity.resolve`），路由层的拦截会漏掉它 —— 表现是「其他端点都拒了，但会话端点仍在发匿名号」。

改动只有三处，13.0 的分支顺序不变：

1. **分支 2 之前**：`if (!anonymousEnabled)` 则跳过 `tp_anon` 解析，并把 `tp_anon` 记入待清除 Cookie；
2. **分支 3**：`if (!anonymousEnabled || !input.allowAnonymousCreation)` → `identity_required`；
3. **分支 4**（session + anon 同时有效）：关闭时仍然清除 `tp_anon`，但**不触发归并** —— 归并的前提是「匿名数据要接到注册账号上」，而关闭后新的匿名数据不再产生；存量数据的归并入口一并关闭是口径的一部分（存量走保留期清理，见 Global Constraints）。

- [ ] **Step 1: 写失败测试（两种开关状态各一组）**

关闭时六条：无 Cookie + 生成端点 → `identity_required`（**这是 13.0 第 3.a 条的反转，最重要的一条**）；持有效 `tp_anon` → `identity_required` 且响应清除该 Cookie；持有效 `tp_session` → 正常解析；session + anon 同时有效 → 解析为注册身份、清除 anon、**不归并**；`createAnonymous` 直接调用仍可用（供重新打开与仓储层测试）；不产生任何新的 `users` 行。

打开时：既有 8 条用例全部保持原行为（回归）。

## Task 7: 文档回写与收口

**Files:** 改详细设计（R-54）、实施计划（P7）、运维手册、`env.example`、Helm values

R-54 要论证三件事：

1. **13.0 第 3.a 条被反转**。原文「生成端点永不因缺身份返回 401」是产品要求的落地点，现在产品要求变了。保留原条文并标注适用条件（`FEATURE_ANONYMOUS_ENABLED=true`），而不是删掉它 —— 删掉会让将来重新打开时无从还原口径。
2. **3.6 的双模式收窄为「代码保留、入口关闭」**。R-13 的两个关键设计判断（统一 `users` 表、脱敏投影列级 GRANT）都不受影响，前者反而是这次能靠一个开关关掉的原因：如果当初选了独立匿名表，关闭入口会牵动 4 张表的归属列。
3. **失去的与得到的**。失去：首次生成的门槛提高（转化漏斗前置注册墙）。得到：RISK-11（匿名刷 AI 成本）整条消失、TP-1-39 的匿名创建限速失去对象、TP-4-17 的匿名 AI Hero 额度 0 成为空规则 —— 三处复杂度变为休眠。

运维手册补一节「如何重新打开匿名入口」：改一个环境变量 + 重启 api，无需迁移、无需数据修复。

## 预计交付边界

- 匿名代码路径成为**休眠代码**：仍有测试覆盖，但生产上不可达。`travel_identity_total{event="anonymous_rejected"}` 归零之后才可以考虑真正移除（那会是另一个迭代，且需要破坏性迁移）。
- P6 的 `anon/` 存储空间对**新产物**不再产生，但存量对象仍在，且 R-51 那半个未实现的到期清理缺口**依然存在** —— 关闭匿名入口不会让它自动消失，只是让它停止增长。
